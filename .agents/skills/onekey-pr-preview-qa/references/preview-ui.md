# App UI 来源与预览验收

所有交互预览按需读取。本文件保留界面、交互和交付链接的详细验收；主技能只说明选择与门禁。

## UI 必须忠于对应版本的 App

- 优先复用固定 SHA 下原页面、原组件和项目已有样式、设计 token、图标、字体与真实字典。源码中的父容器、平台分支及主题上下文也属于 UI 依据。
- 用户说“现在 App 的展示”时，核对对应 PR 版本、平台、主题与语言；需要当前版本对照时单独固定其 SHA。不能拿最新 x 的样式拼接旧 PR 后声称是该 PR 的真实界面。
- 不自行美化、换布局或颜色、重排层级、改按钮位置/名称、补不存在的产品控件或交互。模拟状态选择器、版本切换、步骤说明、测试结果均放在产品画面外，工具样式与产品样式隔离。
- 重建时分别记录布局/样式与 token/真实字典来源及指纹，图标字体按实际使用记录。关键材料缺失时只交付可核实片段或已有固定版本截图，列出缺失项；不凭经验填成整页。
- 预览清单记录产物、源码、样式和文案材料的 SHA-256。字节指纹证明材料身份，不能证明视觉相符。实际对照对应版本 App 截图或原组件的布局、间距、字体、颜色、图标、文案、disabled/loading/error 状态，保留对照材料和差异观察。
- 没有对照证据时明确写“源码重建，视觉一致性未实测”。原组件缺少真实父级/字体/主题时标注具体差异。图片上标注的 HTML 重建不能替代真实 App UI 验收。
- 复用 `scripts/pr-preview/preview.mjs` 的外壳可减少重复制作。它只承载预先审阅的本地独立展示产物，不含钱包 UI；不能将工具外壳当作设计依据。使用限制与命令见 [execution-tools.md](execution-tools.md)。

## 静态交付与外部受控交互

直接打开的本地页默认静态：产品脚本关闭，只验证真实渲染画面和外壳操作，产品交互记未验。不要通过改按钮样式或添加产品控件假装可交互。只有脚本加载壳、缺实际渲染内容时，先在合规环境取得原组件静态产物或截图，不能把空画面作为 App UI 交付。

CSP 和 iframe sandbox 不是完整的外部断网机制，也不能只凭浏览器 request 监听断言没有 WebRTC 等网络活动。需要产品脚本时，固定受控入口 URL，保留实际禁网和无凭据边界日志及指纹；用户实际打开的入口仍须具备同样条件。生成器只核对上游边界记录，不代替操作系统或容器隔离。

交互输出在 file:// 直开或实际 URL 不符时关闭产品脚本并说明原因。静态片段链接保留实际导航语义与产品样式；本工具不支持的交互片段导航明确阻塞，使用原页面入口或已确认的业务适配器，不默默改产品行为。

## 预览层级与详细操作

按每个验收点实际经过的入口和依赖确定证据等级，记录提交 SHA、平台和测试数据。

1. **真实页面路径。** 从产品入口进入实际页面，路由、父页面状态及决定该验收点的门禁都生效，才可报告该路径已验。实机测试另按用户指定的平台和授权执行。
2. **原组件隔离。** 独立挂载原组件、深链绕开父页面，或用测试桩替代影响结论的路由、只读状态或授权判断时，标记“原组件隔离”，写明绕过的上下文。组件内点击通过只支持该层级。验证父页面只读限制时，还要从真实父入口执行同一点击并观察结果。
3. **源码重建预览。** 根据固定源码的布局、文案与状态，用已审阅的展示逻辑及合成数据重建交互。标明重建的平台和待验项。缺少对应源码时按第 3 节报告缺口。

**最终打开方式。** 交付含 PR 可执行代码的预览时，验证用户打开的入口具备与测试运行相同的隔离条件，包括无凭据、无用户配置挂载及无生产网络访问。无法为用户保留这些边界时，交付可直接打开的本地重建页，检查页面及其依赖只使用已审阅的展示代码与固定数据。验收脚本的禁网设置只对该次运行有效。报告可另附原代码在隔离环境运行的结果，画面旁的等级以用户实际打开的产物为准。

#### 打开和操作预览

- **场景直达。** 报告中的可预览验收点及普通展示或交互发现，链接到对应版本的具体场景。打开即定位到变化处，恢复该场景的平台、内容视口宽度、语言、固定示例数据及起始步骤。使用预定义场景 ID（如 `#amount-detail-de`）或独立场景文件，使空上下文首次打开和同窗口刷新都能还原约定状态。只有一个场景时，直接指向该状态的页面即可。需要验入口路径时提供“从入口开始”，让测试者按产品原有步骤到达变化处。
- **改前 / 改后。** 比较起点有源码时，默认在同一内容视口原位切换。保留平台、实际 CSS 宽度、语言、输入及操作进度；各版本按自身逻辑执行相同操作。在首个不可执行的动作处停止，显示缺少的步骤和实际停留位置。即使两端都有后续动作，也保留该分叉；用户在分叉处主动操作后，从眼前的状态继续。仅当两侧各自实测的内容宽度都等于目标宽度时启用并排；窗口缩窄后回到原位切换。另行展示开发分支时标明 SHA。
- **多步复位。** 多步场景提供“从头再试”，恢复该场景约定的初始步骤与固定数据，保留选中的版本、平台、视口和语言。清除上轮草稿及模拟请求，确保迟到的回调不会改写新一轮状态。以当前场景状态及仍有意义的分叉恢复视图，调整宽度或语言时避免反复执行已结束的操作。示例：从同一失败场景分别走“重试”和“取消”。版本切换、复位和模拟状态控件放在预览工具栏，产品画面保留源页面的按钮与布局。
- **画面旁的证据。** 在产品画面外紧邻当前视图标明平台、版本、渲染来源及影响此场景的主要 mock 或待验项。随场景和版本切换更新，并排时各列分别标注。例如“Desktop · 原组件隔离 · 模拟行情”或“iOS · HTML 重建 · 原生手势待验”。整页报告沿用相同口径。

#### 按改动还原界面

- 尺寸依据实际源码断点，测试断点前/等于/后；移动 320/360/375/390/393/430 等 CSS px 或逻辑点按需选取，桌面按实际断点（如 768/1024/1280/1440/1536）选取。标清模拟视口与原生实际测量的区别。
- 支持与改动有关的页面入口、弹窗、输入、选项、切账户/网络/币种、分页、Tab、开关、正常/错误状态、语言、浅色/深色切换。不要机械加入无关控件；新增控件须有真实响应。
- 语言优先从固定 SHA 字典读取；默认中文/英文，并按风险选择德语、法语、俄语、日语等。没有实际字典时明确标注示意文案，不宣称等同于原文。
- 使用示例账户、虚拟地址、无资金测试数据和可控行情；不连接生产接口、真实签名、广播，不展示密钥、助记词或用户隐私。真实二维码与交易链接若不能安全核实，使用明确的演示占位或禁止跳转。
- 为已确认的普通交互或展示问题提供可一键切换的场景，清楚标识“当前实现 vs 正确预期”。风险模拟单独注明假设与待验证条件，不将推断表现呈现为既成事实。
- 根据本次改动检查实际渲染、脚本异常、长文案和断点布局。将受影响的长文案与断点前、等于和后的宽度组合，检查横向溢出、垂直裁切及异常的内层滚动，保留产品设计中的滚动行为。测量注明实际构建、原组件隔离或重建的层级。

#### 验收最终链接

快速首轮按本轮实际交付的链接和风险选择下面的场景。每条链接的首开、关键交互、刷新和版本核对必须实际完成。其他适用的偏好、宽度、语言、重复回放与状态组合列入待补清单。

1. **冷启动与刷新。** 每条最终链接各用一个无该预览历史的浏览器上下文首次打开。核对画面、版本、语言、实际内容宽度和场景数据；同一配置中新开的窗口可能继承旧偏好。操作后在同一窗口直接刷新，再核对约定首屏和操作。若偏好也参与初始化，另用已保存相反偏好的上下文核对链接恢复规则。
2. **版本分叉。** 若两版流程不同，走过仅某版支持的中间步骤，再执行两版共有的后续动作并换版。核对首个分叉、实际停留画面、旁注及宽度，检查切回原版本和在分叉处另作选择的结果。
3. **关闭与复位。** 对样例支持的按钮、键盘（如 Esc）或返回操作，直接读取面板或弹窗的可见状态，交叉核对旁注、切换版本和复位结果。通过键盘打开后，从画布内关闭时检查焦点回到打开按钮，确认可直接重开。若工具栏也支持 Esc，先把焦点移到工具栏再关闭，检查同一控件仍有焦点，继续按 Tab 或 Shift+Tab 能按原顺序移动。切版后也核对工具栏焦点。重复完成相同流程后切换宽度、语言或版本，核对达到相同状态所需的回放量，记录对比次数。
4. **交付入口。** 按用户实际收到的文件或隔离入口验证资源及其执行边界。逐条读取页面或其绑定清单的完整比较 SHA，与 Step 1 复核的验收点起止 SHA 对账，另核对场景指向的版本。比较范围变化时更新并重验受影响页面。暂不能更新的链接明确标为历史证据，当前验收点保留验证缺口。载体丢失锚点时改用独立场景文件并重验。只报告实际适用且已执行的检查；无法打开浏览器时注明“预览交互未验”。预览作为本地临时产物交付。
