# 差分测试（Differential Testing）

适用：所有有行为变更的 PR。主技能的固定基线、授权和证据规则继续生效。

默认快速首轮优先验证所选关键路径的 B/H 差异，固定比较 SHA。T/M 合入检查按契约风险优先安排，尚未执行时列为合入兼容待验证。完整/深度模式展开以下所有适用比较，结论只引用实际取得的证据。

## 1. 比较对象

| 对象 | 作用 |
| --- | --- |
| B：实际比较起点（merge-base 或合入前提交） | 改动前行为、回归归因 |
| H：固定 PR head 或实际合入终点 | 当前变更的实现 |
| T：未合入 PR 的实际目标分支在本轮固定的 SHA | 合入前目标分支的表现 |
| M：T 与 H 在隔离环境生成的临时合并树 | 记录 tree SHA 或本地合并提交 SHA，检查两个固定版本组合后的行为 |
| X：可选开发对照分支的固定 SHA | OneKeyHQ/app-monorepo 默认取 x，其他仓库仅检查用户显式指定的对照分支。用户指定优先，对照分支缺失时注明，继续检查 PR |

未合入时固定实际目标仓库、分支、T 和 PR head H，求两者的 merge-base B。用 B/H 检查 PR 自身的变化。当目标已从 B 前进，沿实际调用链比对两边的改动。同一文件的改动，以及位于不同文件的调用方与提供方、字段类型与消费逻辑、公共接口与实现都可能相互影响。有契约关联时，在隔离环境中按同一 fixture 分别验证 T 和 M。即使 Git 能干净合并，也要检查受影响的实际入口。

已合入时，B 取目标分支实际合入前提交，H 取该 PR 最后一笔实际合入提交。记录原 PR head 与这个区间的关系，按真实区间检查全部合入变化。将后续修复单列，并注明其 SHA。

在本地验证 bundle、导入对象或生成临时合并树时，使用本次创建的独立目录。为 Git 子进程显式构造环境，排除调用方的 Git 仓库定位、索引、对象库和配置变量，隔离用户和系统 Git 配置、模板、钩子、全局忽略规则及属性文件。指定目录后，核验 Git 实际解析的仓库、对象目录及适用的工作树，再执行写入。任一位置或隔离条件无法确认时，将该验证记为阻塞。合成调用方的初始化也隔离全局忽略和属性，避免夹具文件被跳过或改写。验证实现时，用独立的合成调用方仓库核对前后 HEAD、配置和对象库指纹。

## 2. 控制变量与实施

1. 列出明确允许变化的验收项与必须保持的不变量（包括旧入口和已有功能）。未确认的预期不进入强制断言。
2. 两套代码使用等价的依赖、平台、配置、fixture、初始缓存、时钟、随机种子和事件序列。若锁文件、原生模块或依赖正是变更点，按各自提交正确依赖运行并说明差异；不得强行共用不兼容依赖。
3. 优先从两份原始源码调用相同公开入口，或隔离渲染同一实际页面。为两端建立共同输入适配层，但不得重写受测逻辑来使结果一致。记录测试桩以及不可比较的部分。
4. 记录每步状态、输出、调用顺序与 UI 可观测结果。必要时捕获网络请求、store 变化、最终 payload 和异常。仅规范化随机 ID、确定无业务意义的时间或顺序；不得把币种、精度、金额、地址、网络、状态及关键时序差异归一化掉。
5. 先判定各版本是否符合独立预期，再比较 B/H；B 与 H 相同不代表都正确，变化也不自动等于回归。新功能在 B 不可达时，记录“不适用”，比较可复用的不变量、相邻旧路径和 H 的新验收。
6. 对重大变化追加负向数据、恢复操作和边界；相同用例保存为可重复 fixture，记录命令与实际执行环境。没有环境时做静态分支对照，不称为已运行差分测试。

## 3. 比较维度（只选受影响项）

- UI：DOM/布局、文本、按钮状态、路由、焦点、可访问性、主题及断点；截图差异只作定位线索，排除非确定性行情和动画。
- 业务：公式、数值精度、排序/筛选、状态转移、时间边界、隐私显示、异常恢复。
- 数据：账户/链/资产身份、余额、缓存键、请求参数、调用次数及失效机制。
- 交易：报价归属、build、review、sign、待广播参数；所有危险调用使用隔离拦截。

## 4. 结果判定与记录

分别判定 B/H 的 PR 自身变化和 T/M 的实际合入影响。若同一必须保持的契约在 T 满足、在 M 违反，先记录合入回归，再用 B/H 解释根因。两组比较结论可以同时成立。

| 分类 | 说明 |
| --- | --- |
| 预期变更 | 已确认需求要求改变，H 符合独立断言 |
| 新引入回归 | B 满足契约，H 在可达条件下违反契约 |
| 合入回归 | 同一 fixture 在 T 满足不变量、M 失败。B/H 都通过且仅 M 失败时，核对两侧组合产生的兼容性问题。B/H 已有同样失败而 T 已修复时，记录合入使已修复问题复发。H 已引入回归时，同时记录其在 M 的实际表现。用调用链验证归因 |
| 目标分支已有问题 | 同一失败已见于 T 与 M，核对失败原因和影响范围。若 M 扩大影响，单列差异 |
| 既有问题 | B/H 均违反契约；仅与本次改动相关时报告 |
| 既有问题扩大 | 旧缺陷在 H 出现新增入口/触发范围/影响，注明差异 |
| 已修复 | B 有问题，H 在同一有效场景下正确；只纳入必要回归 |
| 未确认/不可比 | 预期、依赖、运行环境或触发条件不足；说明缺口 |

例：零值在 B/H 显示“–”，T 修复后显示“0”，干净合入后的 M 又显示“–”。同时报告 B/H 的旧症状和 T/M 的合入回归。

| 场景/fixture | 独立预期 | B | H | T（适用时） | M（适用时） | X（按需） | B/H 结论与证据 | T/M 结论与证据 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| ... | ... | ... | ... | ... | ... | ... | ... | ... |

合入检查只在干净隔离 checkout/worktree 中进行，不修改用户现有分支、不 push、不提交 PR。不自动处理冲突使其通过；冲突、构建失败、未能复现的依赖分别记录。真实目标分支无法获取时，保留兼容性缺口而不是猜测。
