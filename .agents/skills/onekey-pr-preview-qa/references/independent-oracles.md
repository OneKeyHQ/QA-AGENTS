# 独立业务断言与断言有效性

适用：所有业务断言，包括源码测试、差分测试、回归预期。核心原则：不能用被测实现本身计算 expected，再断言其等于 actual。

## 1. 选择独立依据

优先使用最新已确认需求、协议/服务契约、可验证的独立参考数据、既有已确认不变量及仓库业务规则；依据必须与当前网络、协议、币种、版本、接口参数和时间一致。不是所有功能都必须外查官方资料，只有实际需要且可访问时才查。外部协议规则与 OneKey 的特有业务口径不一致时先区分，不直接把外部产品行为当成 OneKey 要求。

| 模块 | 参考来源（按实际适用选择） | 核对重点 |
| --- | --- | --- |
| Perps | Hyperliquid 对应版本官方规则、API/WS、独立高精度公式 | 多空、杠杆、ROE、触发价、预估强平价、盘口、仓位与订单 |
| Swap | 同次原始报价、渠道契约、构建参数、独立交易解析 | 网络、币种、金额、收款地址、授权、最小可得、有效期 |
| DeFi/Earn | 协议文档、合约 ABI/状态、可信区块快照、服务端契约 | 份额、净值、收益、赎回、奖励资格、到账状态 |
| 钱包资产/History | 独立链上余额/交易、同一时间/区块的估值来源 | 余额、聚合去重、单位、法币总额、资金流向 |
| 返佣 | 确认的比例、原始交易量与返佣规则 | 阶梯、精度、统计区间、账户归属 |
| i18n | 实际语言字典、项目格式化规范、locale/ICU 规则 | 单复数、分隔符、占位符、日期、输入与提交的分离 |
| UI/交互 | 已确认设计、验收点、可观察交互契约 | 顺序、可点击性、禁用、显示条件、焦点与导航 |

记录来源链接/路径、版本/SHA、时间/区块（如适用）及关键参数。外部来源、服务端计算无法核实则只能验证前端对给定 fixture 的映射与不变量，不能宣称端到端业务正确。

## 2. 断言设计

- 计算场景：用独立公式或预先计算的常量数据表，使用高精度十进制/整数最小单位，单独考虑舍入、手续费、合约精度和可接受误差；不得用生产公式的同一函数生成期望。对浮点/时间容差说明依据，不任意放宽。
- 同一 fixture 的预期先写下来，再读取/执行实际结果；不根据实际结果回填期望来使测试通过。
- 若仓库公共 formatter 作为某调用方的独立契约，可用它检验调用方是否接入正确，但测试 formatter 本身时必须换成独立 locale 样本或标准规则。复用同一生产实现不是独立验证。
- 无明确数值 oracle 时使用业务不变量：例如无报价不得提交；旧账户响应不得覆盖新账户；更换显示语言不改变最小单位金额；签名对象与确认页一致。适用时增加性质/变形测试，例如同值换单位或逆向换算在正确精度内保持一致；不强行假设所有协议单调、可逆或 1:1。
- 分开检查前端显示、客户端提交、服务端决策与链上结果，不越过证据边界。

## 3. 强制负向断言自检

对核心资金/权限、关键计算、数据归属及状态保护断言，至少选一组已知正确数据和一组确定错误数据，确认测试能够区分两者。优先直接对断言输入注入错误值；若需要 mutation test，只在临时测试副本/适配层做小范围变异，不修改真实 PR 源码，不将变异后的失败归因给 PR。

| 错误注入 | 断言必须识别 |
| --- | --- |
| 修改收款地址/网络/账户 | 不一致时失败，而不是只检查字段存在 |
| 金额偏移一个最小单位或超过已确认容差 | 精度或金额差异 |
| 用旧请求响应替代新数据 | 作用域或请求世代不匹配 |
| 将禁用状态改为可提交 | 状态保护失效 |
| 删除关键返回字段或把 `null` 改为 `0` | 缺失值与业务零值的区别 |

错误样本仍通过时，修正断言并重跑；无法运行时标记“断言未做负向自检”。不要报告伪造的 mutation 覆盖率。对关键断言不足的测试，即使运行无失败，也不得作为强通过证据。

## 4. 证据记录

每个关键断言记录：断言对象、独立预期来源、输入、预期、实际、负向自检状态、容差（如有）、执行层级和缺口。必须区分产品尚未确认的预期与明确逻辑不变量。
