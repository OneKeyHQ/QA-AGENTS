# 独立审查与反证门禁

适用：所有拟报告的代码发现；大型或高风险 PR 进行额外独立专项审查。目标是减少误报和漏报，而不是让多个角色重复输出同一个问题。

## 1. 按风险分工

小型 PR 可由一个执行者分阶段处理；大型/高风险 PR 在具备实际子 Agent 能力时按独立角色拆分，遵循 QA-AGENTS 的现行调度限制（例如该仓库的 max N=2 并发约束；若已变更，以读取到的最新规则为准）。角色不等于必须启动同等数量的 Agent。

| 角色 | 职责 |
| --- | --- |
| QA Director/协调者 | 固定 SHA，确定范围、验收口径、执行预算、证据和交付门禁 |
| UI | 真实平台分支、双端预览、交互和布局实验 |
| Logic | 独立 oracle、计算、状态、边界、异步与缓存 |
| Security | 资金/权限、实际签名与提交边界、危险调用隔离 |
| i18n | 真实字典、数字/时间、语法、长语言与输入解析 |
| Regression | 正反向调用链、已确认需求/已有用例、最小回归范围 |
| Runtime | 差分、异常注入、源码定向运行及可复现证据 |
| Verification | 独立复核/反证候选发现；重新读源码和实际测试输入，不能只认可前一角色的结论 |

多个角色可合并；避免不同角色共同修改同一测试文件或正式规则。独立角色共享固定基线、需求、fixture 和授权范围，先形成独立判断，再交换证据。普通功能可交换最小复现。安全发现交叉检查保护条件、固定源码和防御性断言。不具备独立 Agent 时，顺序进行第二次独立阅读和适用的断言复核，并注明实际方式。

## 2. 每条发现的反证清单

1. 需求：当前预期有已确认来源或独立不变量吗？是否把产品选择、旧设计或个人偏好误判成 bug？
2. 基线：实际运行的源码与比较 SHA 是否一致？优先从固定提交导出或用干净快照复测。确实采用本地改动时，在报告中注明来源。对用到的未提交规则、Skill 或 fixture 记录相对路径、工作区状态和实际字节的内容哈希，必要时在本地报告目录保存脱敏快照。提交 SHA 只标识该提交已有的内容。对照 B/H；若目标前进且存在契约关联，分别核对 T/M，按差分专项归因。
3. 可达：从产品入口进入时，父路由、只读父容器、平台/账户/网络门禁是否实际生效？核对事件是否到达目标处理器，并检查 feature flag、上游验证与下游修正。组件隔离实验应列出绕过的父级条件，重建演示只提供模拟画面的证据。
4. 证据：是否实际执行原函数/原组件，而非仅重写模拟？测试桩是否改变真实契约？人为延迟是否存在真实对应路径？复现时序、数据和实际输出能否重跑？
5. 影响：用户实际看到/提交的是什么？是否只是中间状态、开发环境、非用户可见数据或正常降级？资金问题核对到哪一阶段？不能把中间字段异常直接当成已发生损失。
6. 验证：独立预期、负向自检是否有效？优先对高影响问题换一组有效数据或反向操作复测；复现失败时检查环境差异，不掩盖反例。
7. 去重：同根因的多个表象合并但保留触发路径；已修复条目不再次当作当前缺陷。旧评论或 AI review 不是独立证明。

## 3. 结论门禁

| 反证结果 | 处理 |
| --- | --- |
| 证据成立 | 按实际确认状态、严重程度和归因输出 |
| 有条件成立 | 标需验证风险，列具体前提及最小验证动作 |
| 产品口径未明确 | 标需求确认，不能计入确认 Bug |
| 已有保护/不可达/已修复/无实质影响 | 不列为当前缺陷；必要时保留回归项 |
| 复核资料不足 | 保留证据缺口，不能声称完成独立验证 |

对于高影响发现，有明确静态因果及可达条件时可静态确认；缺少真实签名/提交或接口证据时只确认已证明的行为层级，严重程度按仓库定义评估。不得为凑够数量报告无依据的风险，也不得因为另一个 Agent 没发现就自动驳回有证据的问题。

记录每条发现的复核方式（真实子 Agent 或顺序自查）、关键反证、证据层级、结论及 SHA。交付前重新读取 PR 状态、head、实际目标仓库/分支及目标 tip，与本轮固定值核对：

- head 改变或 PR 更换目标时，重新取得 T/H、计算 merge-base B，复核完整 diff、受影响的调用链与结论。即使 head 没变，更换目标也可能改变 PR 范围。
- 目标分支前进时重新计算 B。B/H 未变可复用 PR 自身的证据，对受影响的合入兼容性使用新的 T/M 重测。
- PR 在本轮内合入时，确认合入方式及实际起止 SHA，按合入区间复核。临时合并树的实验只代表当时的 T/H 组合。
- 从最终交付入口读取每个场景绑定的完整比较 SHA 和所选版本，与报告对应验收点的复核版本对账。更新并重验受影响的链接，或按历史证据标注旧页和对应缺口。
- 无法重新获取资料或完成复核时，报告已验证的 PR 状态、目标、起止 SHA 与验证时点，列出变化或最新状态未知、尚未复核的范围。代码行号与运行结论保留在已核验的版本。
