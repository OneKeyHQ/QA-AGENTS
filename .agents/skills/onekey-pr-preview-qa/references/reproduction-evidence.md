# 最小缺陷复现脚本与可重复证据

适用于普通功能缺陷，例如格式化、布局、加载和恢复。优先交付实际可执行且稳定的最小复现。工具或源码缺失时交付明确手工步骤或未验证脚本。安全发现按主技能记录固定源码、保护条件、影响、修复建议和防御性断言。

## 1. 选择最小层级

| 类型 | 优先方式 |
| --- | --- |
| 计算/格式化/纯逻辑 | 原函数的 Jest/现有测试框架或隔离脚本，独立预期 |
| Hook/store/异步 | 实际 hook/service + 受控 promise、fake timers、mock store/API |
| 组件/布局 | 原组件隔离渲染，项目现有测试工具；本地浏览器仅验证临时预览或授权测试页面 |
| 端到端/设备问题 | 真实 App 独立流程中的 Playwright CDP、Appium 等仓库允许的方式；本技能默认不启动真实 App |

遵守仓库实际测试框架、连接和运行规范；不使用与 QA-AGENTS 冲突的方式连接真实 OneKey。重建 HTML 只验证模拟自身，不作为真实 App bug 复现脚本。缺少原始依赖时优先复用仓库现有脚本或交付静态证据，不用同逻辑重写冒充原始函数测试。

## 2. 复现脚本门禁

1. 固定源码 SHA、依赖/锁文件、测试命令、工具版本（可获得时）、平台、fixture、时钟、seed 与所有 mock 边界。记录任何为了可执行而加入的适配层；不修改原始业务逻辑。
2. 从已知初始状态执行最短必要序列，真实调用被测函数或组件，断言具体错误结果/被违反的不变量。结果确定后，尽可能删除无关步骤、冗余数据与环境依赖。
3. 优先使用“正确行为应通过”的回归断言：存在 Bug 的 H 应失败，修复后预期通过。若使用观察性探针（断言当前错误现象以复现），必须清楚标记为诊断探针，不把“成功捕获 Bug”说成产品测试通过。
4. 按验收点记录执行结果。有效断言符合预期时记“已执行·通过”，观察到与独立预期不符时记“已执行·失败”。例如，有效输入下产品入口实际开始执行并白屏，入口可打开这一验收点记“已执行·失败”，未到达的后续业务断言记“未运行”。缺少依赖、fixture 或测试脚本错误使入口无法可靠执行时，受影响的点记“阻塞”。保留各点已有证据、最后到达的一步、预期、实际、错误来源及退出码。退出码仅用于辅助归因。
5. 在 B/H 或修复后的新提交运行同一 fixture。高影响或时序相关发现尽可能重复验证，记录实际次数。无法获得可比较的执行结果时说明缺口。
6. 只使用无资金、脱敏/合成测试数据，网络请求和危险调用隔离；不把用户凭据、日志中的敏感字段、真实钱包秘密写入脚本或报告。

## 3. 临时交付格式

按能力生成最小脚本及必要 fixture、运行说明、实际结果；目录优先遵循仓库已忽略的报告/临时目录或隔离工作目录。不得默认提交源码仓库、写 Jira、维护正式用例文件或通过强制 add 绕过忽略。脚本和报告仅在确实创建并检查路径后提供链接。

每次复跑使用不会与首次交付、既有复跑或同时运行的任务冲突的目录。比较清单可读时，在预检判定前记录它的来源、字节指纹和完整的有效 base/head SHA，以便区分在同一项被拦截的不同输入。无法读取或解析时记录已取得的输入信息和阻塞原因。

运行前列出待验项。每项验收完成后把观察加入本次结果，首开和刷新分别落定。若中途失败或取消，保留已经完成的结果、最后到达的步骤和未运行项。分别记录浏览器断开等环境阻塞、手动中断和有效断言失败，有信号及退出码时一并保留。一经确认，先保存原断言的步骤、错误信息及可披露的预期值、实际值和比较方式。保留 `false`、`0` 和正则表达式等有意义的值。JSON 归档中的 `-0` 用带类型的值保留符号，例如 `{"type":"number","value":"-0"}`。略去敏感值和未经核验的结构，需要解释时另记类型或脱敏摘要。浏览器断开后继续有界等待已启动的清理；期间到达的错误单独保存，逾期则标注仍有清理待确认。

并发测试为各子进程设置与规模相称的超时。受监督的复跑在启动时分配唯一标识，子进程通过专用通道报告进度及结果，监督方按各自截止时间判定并发布唯一的最终归档。固定初始验收计划，独立保存经核实的最新进度。接纳进度前校验工作流、失败摘要、断言及清理错误等已知可选字段的结构。遇到空、截断、形状错误或倒退的进度消息，继续使用上次确认的快照，后续有效进度可以继续推进。发布通过前核对声明通过、声明与实际退出 0，并分别对照初始计划和已确认进度。预览运行核对场景状态、文件观察、扩展检查和比较输入。终态矛盾、缺失或证据不完整时，归档为协议阻塞，保留最后确认的进度，单列缺失或无效的字段及可用的终态摘要。预检已阻塞且输入不可读时，照实留存已有的比较信息。

已确认的工作流、原断言、主要失败摘要和清理错误在终态省略时继续保留，合法的失败终态也沿用已有摘要。终态另有不同的有效摘要时保留两个来源。按初始计划逐项确认必跑工作流已通过，确认过的未完成状态只有在取得相应完成证据后才能推进。有必跑项未通过、原断言明细或顶层断言失败摘要时，将通过声明归档为协议阻塞。终态提供的主要摘要缺少阶段等必需字段时，记录协议错误并保留可披露的摘要片段。即使其他必需证据缺失，也在协议诊断中保存经结构核验的终态独有断言，包括步骤、预期值、实际值及比较方式。回读时核对原始进度和失败记录，明细为空也要保留已有摘要。终态覆盖已确认记录同样按协议阻塞处理。

监督方实际到达执行截止时记录超时阶段，并用该阶段填写返回结果和最终归档的主要失败说明。runner 收到停止通知时的阶段或错误可以另存为诊断。提前收到的子进程超时声明作为协议诊断。监督方观察到 runner 退出后，归档记录原始退出码或信号、实际观测时点、单调时钟耗时和执行预算；未观测到退出时注明缺口。退出后有界收尾 IPC 及输出管道，收尾逾期单列诊断。归属查询和归档 I/O 都使用异步执行，确保其他任务继续处理自己的退出与截止。写入失败时记录落盘错误，同时返回原判定、阶段、进度和已收集日志。

监督进程收到 Ctrl+C、终止信号或触发自动超时时，先核实执行进程自身的会话，再通知活跃任务停止。最终清理期间接受中断后，命令退出码与该次归档的中断结论一致。结果已确定并开始发布时，以这一结论完成同一份归档。正常登记使用监督端探针和执行端等待 ACK 共用的截止时间。runner 在 ACK 前异常退出时，保留已完成的进程树、会话及成员身份核验，另用有界清理时限完成尚有依据的核验。组长也退出时，对两次存活归属快照中身份一致的成员，保留其已核实依据并复核当前身份。原成员缺少运行标记时仍可据此清理。新出现的成员需核对本次运行标记和内核会话。历史归属组内仍有未核实成员时，仅向当前已复核的成员发送信号。归档列出未完成复核的存活候选及原因，其他已独立确认归属的进程继续清理。超时或中断均保留退出码、来源、阶段、最后确认的进度和已采集日志。

结果落盘后按实际字节计算 SHA-256，指纹记录该次结果的相对路径。直接 CLI 先为本次运行使用独立暂存目录，观察与清单核验后一起发布。发布前收到中断时清理自己的暂存目录。结果与指纹经回读核对后再引用。新增或修改复跑保存逻辑时验证两次独立复跑的结果和指纹，读回首次交付的结果和原指纹。若改变了失败处理，同时验证相应的阻塞、失败或中断归档。

```text
repro-<issue-or-short-name>/
  README.md       # 基线、环境、真实运行命令、最短手工步骤及证据限制
  repro.test.*    # 最小复现或明确未运行的测试草案
  fixtures.*      # 仅必要的脱敏/合成数据
  result.*        # 首次交付的实际日志、断言或截图
  provenance.*    # 首次交付的文件指纹
  runs/<run>/     # 单次复跑的结果与 SHA-256 指纹
```

README 至少包含：问题标题、固定比较 SHA、实际平台与测试层级、依赖及准备、运行命令、输入和事件顺序、独立预期、实际输出、断言通过/失败的含义、是否真正执行、尚缺条件、修复后运行同一脚本的方法。没有脚本能力时只输出最短可执行手工步骤、输入、预期、实际（仅已知证据）和源码位置。
