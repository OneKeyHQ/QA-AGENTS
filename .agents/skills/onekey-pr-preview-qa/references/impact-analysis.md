# 反向调用链与最小必要回归范围

适用：公共组件、共享逻辑、store、API、配置、启动链路、平台实现、原生依赖等改变，尤其大型 PR。

默认快速首轮先读取完整变更文件索引，确认所选路径的改动与直接相关调用方。对已识别的独立入口、平台分支和关键风险逐项标注验证状态，广泛反向调用枚举和远程用例去重列为待补。完整/深度模式按下面的适用范围展开。

## 1. 先确定真正改变的契约

- 读取完整 diff 和 base/head 实现，定位变化的 props、默认值、事件、样式、类型、数据字段、依赖及导出函数；区分测试/纯重构、行为变化、生成产物和资源。
- 正向追踪实际执行路径；反向搜索导入、re-export、别名、包装组件、注册表、动态加载、native/web 实现及实际调用场景。结合代码搜索和仓库索引；搜索返回上限、动态调用未解析时注明，不声称全量。
- 不能只搜索文件名、组件名或直接引用。检查调用方是否真的命中改动的参数/状态/平台条件。例如新增可选 prop，默认行为完全相同的调用方不自动判为受影响。
- 涉及共享 store、事件总线、缓存、账户选择器，追踪所有相关读写者、作用域、初始化和重置，确认跨页面/表单/进程行为。
- 涉及原生库、bundle registry、懒加载、平台 stub、路由和包配置，核对运行时依赖、OTA 兼容及回退路径；仅类型检查通过不足以验收安装包。

## 2. 影响分类

| 类别 | 判断 | 测试安排 |
| --- | --- | --- |
| 直接影响 | 当前用户入口实际执行变化分支 | 主路径、边界、异常和恢复 |
| 间接影响 | 共享调用、数据或状态契约的变化传递到其他模块 | 最小代表回归；关键资金或平台差异单列 |
| 调用但不受影响 | 存在引用，但未命中改动条件且能解释 | 记录理由，无须全量测试 |
| 未核实 | 动态调用/代码缺失/平台能力未读 | 标出风险和验证路径，不当作已覆盖 |

建议建立 `变更契约 → 调用方 → 入口/平台 → 影响原因 → 既有用例/新增用例 → 实际验证状态` 的追踪矩阵。正式用例仍使用仓库四列表，不塞入额外列。

## 3. 回归抽样规则

- 优先资金安全、核心状态切换、账户/网络切换、高频主流程，再覆盖局部 UI 与异常。等价平台共享实现时可合并设计用例，但执行结果须注明实际平台；原生、Electron、Extension popup/side panel/expand、Web 和响应式分支存在差异时分别覆盖。
- 共享组件按真实改变的参数、禁用态、主题、点击/聚焦、长文案、加载和可访问性选代表调用方；不因引用数量大直接扩大成全 App 回归，也不只测新入口。
- 结合当前仓库/Jira Test 查漏、去重，记录复用、补充、待确认；未读取的用例不能称为已复用。
- 核心必回归项只在本次有代码影响或用户指定时纳入；必要时补运行时/包级冒烟，但本技能不自动连接真实 App。

例：`AmountInput` 改变 footerSize 默认值与调用方显式传参属于不同影响；`Button` 改变默认 disabled 外观时，需要核对所有真实命中默认 disabled 的核心页面；`Token` fallback 改变时分别追踪原生列表渲染器与通用组件，不能假设所有端均同样使用首字母。
