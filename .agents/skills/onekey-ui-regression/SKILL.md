# 用例驱动的实机回归与脚本维护

入口：`$onekey-ui-regression`；Claude / Cursor 可用 `/onekey-ui-regression`。自然语言提供模块、平台、用例文件和本次范围，例如“Perps，Desktop TF，只读与输入校验”。用户只要求离线补脚本时完成离线阶段，不连接设备。

## 简单口令

用户直接输入 **`回归 perps`** 即触发本 skill，不需要写 `$`、`/` 或长名称。也支持 `回归 <模块>`；模块名不区分大小写。Perps 默认计划为 Desktop TF，读取最新已确认用例，先维护脚本再执行只读、输入校验、预览及可恢复的本地偏好场景，最后交付独立报告。用户显式范围优先；只要求离线则不连接设备。

口令不替代本会话首次平台选择、本批账户和操作范围的必要确认；已确认的信息不重复询问。真实下单 / 撤改单、远端账户设置 / 签名、资金操作仍单独确认本批账户与参数，不因一句回归自动获得授权。未指定账户也可先做离线维护和不依赖账户的市场场景。

询问“怎么触发”、引用口令作为例子或要求修改入口，不算执行回归的指令。不要因说明文字中出现另一口令而串联流程。

在当前仓库根目录执行。先读[独立流程规范](../../../docs/qa/rules/code-review-and-ui-regression.md)的共同约束、流程 B 与统计契约，及 `docs/qa/rules/qa-workflow-rules.md`、`.claude/CLAUDE.md` 中对应平台的模块契约 / Test Script Rules。用 `lookup-rules.mjs` 按模块查询、`lookup-knowledge.mjs` 按场景加载知识。若仓库已提供 Perps Desktop 执行配置，另读 `docs/qa/automation/Perps-执行分组与账户前置.md`。

## 先生成 / 维护脚本

1. 读取最新**已确认**用例及每个预期，固定文件指纹。待确认的代码推导建议不进入正式断言或正式覆盖率。已有旧用例若来源确认不明，单列待核实，不能擅自删预期、缩分母或按代码放宽。
2. 按“用例文件 + 场景 + 原行指纹 + 预期子项”建立映射，再指向自动化 ID、步骤、断言文件 / 行、数据 oracle 和证据层。逐项标已覆盖 / 部分覆盖 / 未覆盖 / 待审核，不用脚本函数数量代替用例覆盖。
3. 用 Test Designer 职责生成或维护连续脚本。操作和断言分别可追踪，每项断言检查具体预期；跨入口重新取目标入口证据，不复用源列表快照。数值、身份、时间与数据源独立对账；初始值 / 空样本 / 模拟返回值不能代替真实变化。恢复在 finally 中执行并独立读回。
4. 桌面遵守 `fn(page)`、`setup` 缓存前置、`displayName`、`createStepTracker` / `safeStep` 和正式 Runner 契约；移动端遵守 POM / Appium 契约。选择器由 Knowledge Builder 职责维护 `shared/locators/<module>.json` 后构建，不手改 generated map。运行相关语法、定位器和本地辅助 / 反例检查；此时只报告离线证据。

## 再按授权执行实机

1. 本会话首次连接前选择平台，已选则复用。Desktop TF 只读取当前安装版本，不检测或更新 TestFlight。遵守唯一指定 App 路径与 CDP 连接规则，不关闭用户实例、不调整窗口。若用户暂停，立即停止 UI。
2. 对整段脚本按实际副作用分为只读 / 输入 / 预览、本地偏好、真实订单、账户设置 / 签名、资金操作。公开行情不索取无关账户；账户对账到执行时索取本批观察地址或钱包名 + 账户名并读回核对；真实订单、远端设置、资金操作分别确认本批账户与参数。只读授权不包含启用交易；不得自动下单制造样本。
3. 先满足网络、入口、权限、样本和弹层等前置。可在当前授权内补齐的前置先补后测；确实缺失则逐子步骤记录具体阻塞与补测条件。确认预览的停止点与请求观察边界，不能因“预期失败”就在只读批点击最终提交。
4. 通过项目 Runner 执行已核对范围；Desktop 用 `node src/tests/run.mjs <desktop/模块/已审核文件>`，不盲跑混有其他交易队列的整个目录。Perps `--plan` 仅是离线计划，不是已执行或权限拦截证明。结果保留时间、包版本、账户身份校验证据、用例/脚本指纹、每项断言、截图/日志和恢复读回。身份异常、外部交易干扰或恢复失败时停止受影响 UI 队列。
5. 用 QA Manager 职责区分产品缺陷、脚本 / 断言、环境、缺样本和恢复失败。修复脚本实现可沿已授权维护范围继续；业务预期变化先列待确认建议，确认前不更新手动用例或改验收断言。产品代码只报告诊断与修复建议，不自行修。修脚本后复跑受影响项，保留原失败与新结果；未复跑不得写已通过。

## 独立交付

按规范生成用例—断言映射、覆盖率和实机报告；记录本批维护内容、未执行原因与补测清单。源码隔离、辅助测试与 Desktop 实机分开统计；部分 / skipped / blocked / TODO 不计完整通过。无需执行的纯离线请求写“实机未执行”，不制造通过率。

如引用代码审查问题，保留 A 的证据与结论，在 B 单列已复现 / 本批未复现 / 未执行。此入口不自动开展全量 x 分支审查。沉淀执行经验并检查手动、API、UI 三线影响；用例内容改变仍遵守逐项确认关口。
