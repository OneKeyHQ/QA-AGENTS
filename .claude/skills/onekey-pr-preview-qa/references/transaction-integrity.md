# 资金操作与最终交易参数一致性

适用：转账、Swap/Bridge、Perps、DeFi/Earn、DApp、授权、账户/收款地址、签名、广播及可能影响这些链路的共享组件和状态。

默认仅离线执行：用无资金示例钱包/合成数据，mock 真实签名器、硬件通信、广播、交易提交和具有副作用的 API；网络默认隔离或明确白名单，只允许必要的只读请求。发现危险调用没有被隔离、测试桩可能落到生产服务、或无法确认隔离时立即停止对应执行，保留静态审查。不请求、读取、保存或输出真实助记词、私钥、密码、签名秘密；不产生或广播真实交易。

## 0. 先生成交易主流程测试项

快速首轮也先按本 PR 的交易类型与实际生命周期建立完整测试项，再安排执行优先级。逐项关联入口、源码、前置、步骤、独立预期和验收点，适用时覆盖账户激活、注册、公开转账、隐私存入/转移/取回、费用、确认、签名、提交、查询和恢复。按真实分支设计，实际不存在的阶段注明不适用。

预览按可见变化选择场景，交易代码层可独立生成测试项并执行。优先运行固定版本中的原函数、方法或已有测试，在无副作用替身下核对参数、顺序、调用次数、取消、失败及重复操作。记录实际执行的源码边界、抽取或转换方式和所有替身，保留完整主流程清单及未执行项。模拟签名或广播的结果归入相应隔离阶段，真实环境结果另行记录。

## 1. 追踪实际交易生命周期

从真实用户入口往下追，不只核对 UI 或 quote。为每个阶段记录当前 scope/请求身份和可取得的不可变参数快照。

| 阶段 | 重点 |
| --- | --- |
| 用户选择 | 钱包/账户/派生路径、网络、资产标识与合约、金额与精度、收款地址、操作方向 |
| Quote | 报价的账户/链/币对/金额/收款地址、provider、版本/有效期、手续费、滑点、预估/最小可得等与当前选择匹配 |
| Build | 构建使用有效报价与已确认选择；链 ID、交易目标、方法、参数、token/native value、授权对象与额度正确 |
| Review | 用户可见内容与待签名交易相符；网络/账户/资产/金额/地址/授权/费用等重要变化不得静默替换 |
| Sign | 捕获实际传给软件签名、硬件设备、QR 或消息签名边界的数据；核对签名者、链及 payload；按真实类型解析 calldata、typed data、UTXO、memo 等适用字段 |
| Broadcast/Submit | 捕获待广播或服务端实际执行请求；验证其与本次已确认且已签名的操作一致，无误路由、重复提交或隐式换参 |
| Result/Recovery | 结果归属原账户/交易，余额、持仓、订单、历史刷新正确；处理中、明确失败、未知结果与成功分别处理 |

若某交易没有 quote/build 或阶段合并，按真实调用链标明不适用。派生地址、收款地址、spender、router、合约、费用等不是可互换字段；合约收款/路由等合法转换需依据协议语义独立解析，不机械要求每阶段字节完全一致。

## 2. 核心不变量

- 用户确认的语义交易内容与最终实际提交的交易一致；允许的动态费用或其他变化必须符合已确认规则，实质性变化要重新确认或阻止提交。
- 报价、授权、余额、链、资产、账户及收款地址均绑定当前操作；不同表单、窗口、账户、网络或请求不得共享导致错误归属的执行状态。
- 报价过期/失效、切换币种后取价失败、账户未解析、权限不满足时不得使用旧状态继续提交。不能用 UI disabled 证明底层一定拦截，继续追踪 handler/service/实际签名与提交边界。
- 用户拒签、取消或明确未发送，不得自动提交；广播或提交结果未知时必须先核对原操作状态，避免重复发起。多步骤交易区分已完成的授权/包装/提交与未完成步骤，重试不得重复扣款或错误放行。
- 观察钱包、未备份钱包、旅行模式、硬件限制、网络不支持等按已确认业务规则验证，检查实际执行门禁而非仅隐藏入口。

## 3. 保护条件的回归验证

使用独立的合成 fixture 和无副作用的替身，核对普通操作符合已确认的保护条件。可选取下列断言：

- 确认页显示的账户、网络、收款对象和最小单位金额与本次有效报价及构建结果一致。
- 取消操作后签名替身的调用次数为零。对已失效的报价，界面显示重新报价入口。
- 已知签名拒绝、网络超时及结果未知的模拟响应各自显示正确状态，用户能按需求恢复。
- 按实际业务精度与网络规则检查 Max、费用预留和数量格式。离线结果只覆盖已验证的阶段。

审查中发现保护缺失时，记录代码位置、用户影响、修复建议和修复后的预期。安全发现以防御性核对交付。

## 4. 判定边界与输出

记录最后实际到达的阶段、关键源码 SHA/行号、各阶段快照、断言、危险调用拦截方式以及尚未验证的阶段。地址解析错误可被确认，但未捕获最终签名/提交时不能宣称错误交易已广播或资金已损失。安全风险的严重程度按可达影响评估；不因环境限制自动降低，也不因涉及钱包自动升为 P0。

若有明确资金安全缺陷或重大签名一致性缺口，优先复核并列入 QA 发布风险；真实交易验收必须经独立流程明确授权，不因本专项自动执行。
