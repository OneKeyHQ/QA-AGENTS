# 回归项、代码发现与完整报告

生成业务回归项或整理发现时读取。快速首轮保留主流程测试设计和实际执行边界；完整模式再展开完整报告。

### Step 7 — 生成可执行回归项

参考 `onekey-test-designer` 的 PR 分支中本轮所需规则。有业务回归场景时，覆盖所选主路径、边界、异常与恢复，以及共享调用方最小必要回归。纯文档或配置改动经核实没有业务回归场景时，报告实际检查项和结果即可。快速首轮核对可直接读取的本地用例，完整/深度模式再按实际影响核对仓库与 Jira Test 去重，记录未能读取的用例来源。

快速首轮复用可直接读取的本地用例，先交付本 PR 主流程及直接相关异常的回归步骤，再标明本轮实际执行的子集。资金类主流程按交易类型和实际生命周期逐项列出。远程 Jira 去重列入待补，用户要求同步或完整用例工作时按对应流程执行。

- 适用的手动业务用例严格四列：优先级 / 场景 / 操作步骤 / 预期结果，不加 ID；在章节或前置条件说明适用端及测试数据。Markdown 源文件多行单元格按编号加 `<br>`；无依赖时 P0 排前。等价端/等价参数合并，实际平台分支、资金风险、业务状态或不同优先级则拆开。
- 优先级遵循 QA-AGENTS：用例 P0（资金、安全、风控、主流程、核心状态切换），P1（配置、UI、非主路径），P2（低频、文案、容错）。这是**用例优先级**，与缺陷严重程度独立，不机械等同。
- 必须具备可操作前置、入口、最小复现数据、可观察预期。错误实现作为审查发现，不写入正确预期；没有确认的产品要求列在待确认建议中。
- 对本次改动确实影响的钱包创建、升级/解锁、转账、首页资产、Swap、History/Activity、DeFi/Earn、Perps、Web Embed 等核心功能补最小回归，不无依据扩大全量。涉及硬件时补相应真实设备签名验收项，但此流程默认不执行。
- 对已有用例指出复用/新增/需调整；未经用户确认不更新正式用例、Jira Test、需求文档或规则库。

以下示例假定对应业务要求已经确认。金额示例的预期取自固定样本，错误地使用 en-US 时会得到 `1,234.5`。

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 两个独立 Swap 表单，各自设置收款地址 | 1. 在表单 A 设置外部测试地址<br>2. 在表单 B 切换币种/重置收款选项<br>3. 回到 A 核对预览与待签名参数 | A 的收款选择不受 B 影响；最终待签名参数与本次确认页一致 |
| P1 | 金额详情采用千分位分组、保留一位小数 | 1. 加载原始金额为 `1234.5` 的测试数据<br>2. 将语言切换为德语（de-DE），打开金额详情 | 金额文本显示 `1.234,5` |

### Step 8 — 问题证据、严重程度和归因

确认状态与严重程度独立标注。遵循仓库 `pr-regression-rules.md` 的缺陷级别：

| 级别 | 判断原则 |
| --- | --- |
| P0 | 有可达证据的资金损失、越权或广泛核心功能阻断 |
| P1 | 核心操作或关键资产信息错误、特定条件下核心操作阻断 |
| P2 | 局部展示、提示、文案、适配或低影响错误 |

默认不自行新增 P3；若用户/当前 Jira 规则明确采用 P3，再按其口径使用。不能因涉及资金就自动 P0，不能因尚未实机复现就自动降级。

| 确认状态 | 要求 |
| --- | --- |
| 确认的问题 | 明确需求/契约或逻辑不变量 + 可达触发条件 + 具体错误结果；注明静态确认、原函数/组件测试、或真实环境复现 |
| 需验证的风险 | 有具体源码路径和条件，但还缺真实时序、接口数据、平台表现或执行链证据；记录缺少的证据和适用的验证方式 |
| 产品/需求确认 | 当前行为已知，但正确业务口径尚未确认；不列为已确认 Bug |

按 Step 3 的实际入口标注真实页面、原组件隔离或重建。纯逻辑可标注原函数隔离执行及 mock；静态确认需完整调用链和具体条件。重建只证明展示逻辑。受控时序实验注明真实触发条件是否已证实。CI 和 review 作为辅助证据。

涉及安全漏洞时，以固定 SHA 的代码证据、受影响的保护条件、影响、修复建议和修复后的防御性断言交付。最短操作序列、复现脚本、故障搜索与可交互演示仅用于普通功能缺陷。

每条发现记录以下通用字段。

- `[确认的问题/需验证的风险][P0/P1/P2]`、简洁问题标题及受影响端。
- 引用对应比较终点 SHA 的文件、行号及可访问源码链接；删除内容引用比较起点。仅临时合并树出现的问题分别引用真实目标与 PR 提交中的关键行，并附临时树标识。多个文件仅保留关键因果位置，不能猜行号。
- 用户影响、应满足的预期或不变量、已核实的结果及相应证据等级。
- 归因：本 PR 新引入 / 既有问题被本 PR 暴露或扩大 / 仍存在的相关旧问题 / 目标分支到合入结果的回归（包括已修复问题复发）/ 引入时间待确认。依差分专项分别核对改前与 PR head、目标分支与合入结果。无法确认基线时不得断言新引入。

普通功能发现补充可执行触发条件、最短复现步骤、输入及实验结果，缺少证据时标明待复测动作。安全发现补充相关保护条件、受影响范围、修复建议及防御性断言。

在定稿前按 `independent-verification.md` 逐条反证：寻找上游拦截、后续修正、平台门禁、实际调用链不可达、测试桩失真及新提交修复。高影响问题优先由独立复核角色重新检查；无法独立复核时声明限制，不虚构 Agent 执行。普通功能缺陷按 `reproduction-evidence.md` 交付最小复现脚本和证据，不能执行时仅提供未验证脚本或实机步骤。

只列有证据的发现，按用户影响从高到低排序，同级按证据强度排序。同根因合并，保留各触发路径。**不限制发现条数，不凑数，不重复已修复或无关问题，不以测试缺失本身作为缺陷。**


## 完整报告模板
快速首轮只有本轮范围完成后才报告相应通过，未审阅范围在结论中明确。

```markdown
# PR #编号：预览测试结果

结论：核心行为符合/部分符合/尚不能判断；关键问题和验证边界。
基线：PR 状态、head SHA、目标分支名及 SHA、实际比较起止 SHA、适用的开发对照、关联需求与提测包。注明交付前复核结果。若读取本地未提交的规则或样本，附实际路径和内容指纹。

## 交互预览

受影响端：给出可直接打开变化处的场景链接。注明最终打开方式、渲染来源，以及空上下文首开、关键操作和同窗口刷新的实测结果。
无可见变化：写“交互预览不适用”及判断依据，省略预览链接。缺源码时写待核实范围。

## 验收结果

每行一个验收点和一个平台。有交互预览时，用验收点名称直接链接该场景。以下为同一验收点的两种证据示例，实际报告按观测填写。
非 UI 改动可直接列文档、配置或逻辑检查的对象、证据和结果。

| 验收点 | 平台 | 证据类型与范围 | 实际结果 | 结论及缺口 |
| --- | --- | --- | --- | --- |
| 点击详情打开面板 | Desktop | 原组件隔离，使用模拟数据 | 点击后面板显示 | 隔离验证通过 |
| 点击详情打开面板 | iOS | 仅 HTML 重建 | 演示面板可展开 | 原生点击待验 |

## 源码定向测试、差分与 i18n 结果
按验收点列独立预期、改前/改后观测、通过或失败的断言、阻塞原因与未运行项。合入检查另列同一输入在目标分支与临时合并树的结果及归因。负向自检、交易参数、异常及 i18n 按适用范围报告。

## 覆盖与风险
实际分母、已执行/未执行/阻塞范围；必要时给发布风险建议、包/OTA 验证缺口及工时估算。不得将模拟通过等同于实机通过。

## 建议回归项
有业务回归场景时，按模块提供四列用例，区分新增和复用。
如有需要，另附测试范围、工时与人员拆分；先说明资料/运行缺口及验证边界。
```

最后一节保持仓库 PR 分支的约定：代码发现放在回归项及交付信息之后，完整审查且无发现时写“未发现明确代码问题”；资料不足或审查不完整时写“审查未完成：缺少……；已检查……”，不要使用前述无问题结论。离线测试通过不能代替实机验收；可简洁汇总已执行的实际证据。
