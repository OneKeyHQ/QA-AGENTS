# 异常注入与状态组合测试

适用：请求、异步、缓存、全局/local store、时间、页面生命周期、交互和操作状态。目标是找到普通成功流程难以暴露的错误，而不是列一张未执行的通用 Checklist。

## 1. 建模

先从实际代码整理状态、事件、前置条件、允许/禁止转换、作用域、持久化及关键不变量；标明服务端与本地状态的边界。不要凭想象为产品强加状态机或用模拟状态替代真实代码。

例如 Swap（示意，按实际实现调整）：

| 起始状态 | 事件 | 必须核对的结果 |
| --- | --- | --- |
| 未输入 | 输入有效金额 | 发起属于当前输入的报价 |
| 报价中 | 切换账户/币种/网络 | 新作用域生效，旧响应不能提交或覆盖新状态 |
| 报价成功 | 新报价失败/过期 | 不能以过期报价继续；恢复后才按有效结果提交 |
| 确认交易 | 取消/拒签 | 不执行未授权操作；状态允许按规则重试 |
| 已提交/结果未知 | 重进/重复点击 | 先核对原操作，避免重复提交 |

## 2. 注入策略

| 条件（示例，按真实路径选择） | 重点断言 |
| --- | --- |
| 请求延迟 1/5/10s，或 deferred promise 人为控制释放 | loading、禁用、响应归属、有效性、交互恢复 |
| A 请求晚于 B 返回，或 A→B→A | 作用域+请求世代保护，旧结果不复活 |
| 请求中切账户/网络/币种/语言 | 数据、缓存、quote 和文案均属于当前作用域 |
| 成功后重新请求失败；204/null/undefined/0/空列表/合法缺省字段 | 清理或保留按契约正确，区分零值与缺失，不能静默使用无效旧数据 |
| 断网/超时/恢复/重复回调/取消 | loading/锁释放，恢复入口，提交次数正确 |
| 卸载、关闭弹窗、前后台切换、杀进程重建（可用环境中） | 不落旧导航/异步结果，持久化按规则恢复 |
| 虚拟时钟跨 1 秒、日期/时区、过期或成熟边界 | 截止/状态重新计算；不依赖偶然重绘 |
| 连续点击（例如 10 次）、快速切换、窗口缩放跨断点再恢复 | 防重复执行、草稿归属、焦点、组件重建 |
| 异常 payload、懒加载失败、不可用权限或原生模块 | 局部隔离、清晰错误、可恢复，不能误判整站崩溃 |

优先使用可控 promise、fake timers、固定 seed、事件队列、项目现有测试桩与实际组件，不用真实等待拼凑不稳定复现。禁止在用户真实钱包或生产服务上制造故障；只在安全隔离测试环境运行。故障输入若违反真实接口契约，单独标注为容错测试，不能冒充已证实的线上可达缺陷。

## 3. 状态探索与组合控制

1. 主路径先建立可执行基准；从改动点提取关键状态转换图，识别状态切换中不允许的副作用。
2. 对核心风险覆盖所有相关合法转换与明确禁止转换；优先事件顺序、边界及跨作用域。等价参数合并，普通路径用代表值，关键资金/权限/竞态用明确风险组合补充。可使用 pairwise 作为辅助，不以 pairwise 替代明确高风险组合。
3. 对普通功能的交互或展示状态，若环境支持自动探索，使用有界事件序列、固定 seed 和重置 fixture；例如 2~6 步事件序列，从受影响状态出发，设置合理组合预算与停止条件。记录实际探索数量与漏测，不盲目全组合。
4. 普通功能失败时缩减事件序列和 fixture，确认最短复现。用另一组输入或反向时序复核边界。安全发现按主技能提供固定源码证据，验证已修复或应当生效的保护条件。
5. 真实路径不可达或仅由 stub 人为制造时，标明条件、上游保护和缺少的证据。受控竞态复现不是实机必然复现。

## 4. 输出

记录场景 ID（仅作实验记录）、独立预期、实际结果、测试层级和未验证项。普通功能实验另保存初始状态、事件顺序、注入方式、时钟/seed、调用次数及最小复现。安全发现另记录相关保护条件、影响、固定源码位置、修复建议和防御性断言。通过数只计入实际达到预期的检查。
