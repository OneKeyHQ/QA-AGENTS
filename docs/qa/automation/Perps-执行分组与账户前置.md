# Perps Desktop 执行分组与账户前置

本规则用于后续 Desktop 执行排期。先选择用例、再于实际执行时向用户索取本批目标；离线补断言不要求提供账户。各批重新核对目标，不沿用历史钱包或账户。历史报告与运行证据已于 2026-11-04 按用户要求清理，账户数据批次仍需本批明确目标。

离线执行计划从[测试用例索引](../../../src/tests/shared/perps/data/desktop-execution-cases.json)读取用例身份、原预期、副作用分组与脚本 ID，不依赖可清理的报告目录。该索引不是历史实机证据或覆盖率证明；报告删除后，断言审核状态保守标为待复核。

## 与代码审查的任务边界

用例与最新 x 分支代码审查、TF 实机自动化是两项独立任务，详见[代码审查与实机回归交付](./Perps-代码审查与实机回归交付.md)。代码审查独立输出缺陷/差异报告，完成后不自动执行本文件中的实机步骤。只有用户发起自动化执行时，才按本文件核对当批目标、运行并维护脚本，另交付实机报告。

## 自动化任务每批执行顺序

1. 选定单一队列及具体手动用例行；共享脚本只是候选，必须检查整段步骤，不能因其中一行只读就执行整个混合脚本。
2. 到实际执行时才索取目标：观察组询问完整观察地址或钱包／账户；订单、账户设置和资金组询问各自本批钱包／账户。交易参数按选定场景另行提供。
3. 连接已选 Desktop TF 实例后，通过 UI 选择并读回当前身份与地址，与本批目标一致才继续。观察地址需在 App 中切换／配置为对应观察账户；计划命令本身不导入账户。
4. 先检查既有数据样本及权限：持仓／订单／历史不足则逐子步骤记缺样本，**不自动下单造数据**。观察账户无法进入某些表单校验时，可用用户指定的合适钱包账户；不自动启用交易。
5. 预览确保确认流程开启，并禁止最终确认；输入校验必须确定会在前端拦截，不能将服务端拒绝当只读校验。需要真实网络故障注入、最终提交或并发改单的行进入订单队列，或只跑明确隔离的本地测试。
6. 执行后分别记录断言结果、未执行分支和恢复结果。零请求、订单／余额不变与恢复读回需要各自证据。源码通过和 Desktop 实机通过分开计数。

## 离线清单与配置检查

生成逐行分组（不会连接 App）：

```bash
node src/tests/run.mjs desktop/perps --plan
```

输出在 `shared/reports/perps-desktop-completion-2026-10-29/execution-groups.{html,json,tsv}`。每行保留原手动文件、行号、指纹、原始步骤及预期；手动文档变化会拒绝使用旧分类，要求重新审核。

实际执行前，将 `shared/perps-execution-request.example.json` 复制为 gitignored 的 `shared/perps-execution-request.local.json`，填入本批目标。公开地址形式为 `{ "kind": "address", "address": "完整0x地址" }`；钱包形式为 `{ "kind": "wallet", "walletName": "用户指定的钱包名", "accountName": "用户指定的账户名" }`。

```bash
node src/tests/run.mjs desktop/perps --plan --request shared/perps-execution-request.local.json
```

该入口只做排期与配置检查，输出隐藏目标值；拒绝未知行、重复行、混组、缺账户、交易组使用观察地址及非约定配置字段。它不会执行测试，也不会自动把候选脚本发给原 Runner；输出 `canExecuteNow: false`，仍需实机核对身份及整段脚本边界。现有普通 Runner／Dashboard 不应被当作已具备全局分组拦截。

不将此配置写入转账专用的 `shared/runtime-config.json`，不在报告存储用户密码、私钥或助记词。手动/API 业务预期未改，本次新增的是 UI 执行分组和配置检查。

## 2026-11-03 TF 账户只读复验

本批用户已明确选择当前 TF 地址，仅只读核对；完整目标与版本保存在复验报告（历史报告已清理）和不可变运行清单，不沿用此前交易授权。账户、普通委托、TWAP 与持仓逐行独立比对；外层 Chromium Network 经本地探针校准后检查 exchange 请求。输入／预览只操作本地草稿和关闭入口。

已发现共享表单恢复器错误地重放不同币种的中间快照。中间快照不属于独立用户草稿；只以进入行前的可见表单为恢复基线，完整读回相等，隐藏字段未采集不宣称恢复。恢复失败必须停止队列，保留原始失败；独立恢复并核对后整组重跑，不能回填原失败行。

当前账户没有进行中 TWAP、stopped/error 等样本以及第二个持仓；授权门禁出现时不新增启用交易。依赖真实刷新持久化的测试，在独立请求观察器尚不能证明跨上下文连续观察时单独保留未执行原因，不能删除观察守卫换取通过。手动／API 的业务预期均不因UI执行限制而放宽。
