# Perps Desktop 执行分组与账户前置

维护对象是 `src/tests/desktop/perps/*.test.mjs` 及其调用的共享操作和断言。手动用例只在 `docs/qa/testcases/cases/perps/` 维护，脚本内注明来源；不复制整份手动步骤和预期生成执行计划索引。计划、映射、样本和离线检查不能算实机通过，也不能替代实际 UI 断言。

实际脚本的计算、解析、断言、权限与恢复逻辑可通过 `node --test src/tests/shared/perps/tests/*.test.mjs` 做辅助检查；固定输入只保留这些检查确实使用的最小集合。这些结果不计 Desktop 实机通过率。独立产品源码隔离套件及其运行入口已移除，缺少的 UI 断言仍须直接补脚本。

## 执行边界

| 分组 | 执行时目标 | 允许的操作 |
| --- | --- | --- |
| 只读、输入与预览 | 本批完整 EVM 观察地址，或钱包名＋账户名 | 对账已有数据、校验输入、打开预览后取消；不最终确认，不新增交易授权 |
| 真实订单 | 本批钱包名＋账户名，以及用户确认的交易参数 | 下单、改单、撤单、平仓；点击最终提交的报错、断网和竞态场景也属于此组 |
| 账户设置与签名 | 本批钱包名＋账户名，单独授权具体操作 | 启用交易、远端碎币开关、杠杆等写入，不默认包含下单权限 |
| 真实资金 | 本批钱包名＋账户名，以及金额、网络等参数 | 充值、提现和资金流转，单独授权执行 |

收藏、布局及语言等本地偏好可在只读批次验证，结束必须恢复并读回；恢复失败停止后续队列。缺持仓、订单或历史样本时注明缺什么，不自动下单造数据。

## 执行方式

1. 从最新手动用例选择场景，直接补充对应测试脚本中的操作、预期断言和恢复校验。只实现部分预期的行必须保留 `complete: false` 与缺项说明。
2. 实际执行前确认本批目标，不沿用历史账户。连接已选平台后，通过 UI 切换并读回身份与地址，核对已有样本和交易权限。
3. 检查整段脚本的操作边界；同一模块混有写入步骤时，不能因为其中一项只读就运行整个模块。预览须确认最终提交被隔离；服务端拒单不属于只读输入校验。
4. 使用 Dashboard 选择具体测试，或通过正式 CLI 执行已核对的模块，例如：

   ```bash
   node src/tests/run.mjs desktop/perps/bbo-boundaries
   ```

5. 分别记录代码断言实现情况、实机 passed/failed/skipped、缺样本原因和恢复结果。部分断言或缺样本不能计为完整通过；源码隔离检查通过也不能计为 Desktop UI 实机通过。

旧的 `desktop/perps --plan` 入口及重复索引已删除。CLI 拒绝额外参数，不会将旧命令降级成全模块执行。普通 Runner／Dashboard 没有全局交易分组拦截，运行前仍须检查所选脚本。

代码与用例审查是独立任务，见[代码审查与实机回归交付](./Perps-代码审查与实机回归交付.md)；审查完成后不自动执行实机。手动用例、API 业务预期不因 UI 自动化限制而改写。
