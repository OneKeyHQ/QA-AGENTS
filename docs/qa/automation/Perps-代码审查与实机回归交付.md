# Perps：代码审查与实机自动化独立交付

通用流程、确认关口、报告字段与覆盖率口径以[代码用例审查与实机回归规范](../rules/code-review-and-ui-regression.md)为准。2026-11-03 用户明确两个流程分别触发、分别交付，并要求：先列出代码改动及用例维护建议，用户确认后才更新原有或新增用例。此文取代将它们描述成同一轮回归前后阶段的旧表述。

## A：代码与用例审查

```text
$onekey-code-case-review 审查 Perps Desktop 全部用例与最新 x，汇报 bug、实现差异和用例补充建议，先不要修改用例。
```

默认源仓库 `OneKeyHQ/app-monorepo`，默认开发分支 `x`；每批核验远端精确 SHA。旧源码固定版本与 TF 安装包不能自动称为最新 x。按手动用例逐预期检查调用链，列已审 / 未审范围及缺陷证据；“新引入”须有引入版本依据。

报告同时展示旧预期、当前实现、前置条件和拟修改内容。未确认建议只留在报告，不提前新增【代码推导】用例章节，不改业务规则 / 需求正文或正式自动化预期。用户确认哪些就维护哪些，原手动用例仍用四列并同步可复制版。报告与后续维护记录独立于实机结果。

A 不启动 OneKey，不执行 TF UI，不发布实机通过率；源码隔离检查只是辅助证据。A 结束后不自动触发 B。

## B：最新已确认用例驱动的脚本与 TF 回归

```text
$onekey-ui-regression 基于最新已确认 Perps Desktop 用例补齐脚本，执行 TF 只读、输入和预览回归，真实订单另分批。
```

先建立手动场景 / 预期子项与脚本断言的映射，补齐已确认预期的脚本，再离线检查和实机执行。仅要求离线补脚本则不连接 App。执行按[执行分组与账户前置](./Perps-执行分组与账户前置.md)，本批账户到执行时确认，不沿用历史账户，不下单造样本。

独立报告实际包版本、脚本 / 用例指纹、逐项断言结果、恢复读回、产品 / 脚本 / 环境 / 样本问题、维护记录与补测清单。修脚本后复跑受影响项并保留旧失败；改变业务预期需先列提案等用户确认，不能为通过而放宽断言。

## 报告关系

B 可引用 A 问题编号，附“已复现 / 本批未复现 / 未执行 / 缺前置”，但保留 A 的代码证据与结论；一次未复现不直接关闭条件性源码问题。代码审查进度、源码检查、目标平台断言覆盖与实机通过率分别统计。

本流程不接入 CI、定时监控或后台自动启动 App；不修改现有真实订单、账户设置、资金或外部系统写入的授权边界。
