# Perps - 反手与持仓按钮设置

> 生成时间：2026-10-27
> 规则文档：`docs/qa/rules/perps-rules.md`（§12）
> 需求文档：`docs/qa/requirements/Perps-反手与持仓按钮设置.md`
> 需求来源：OK-63863；源码核对：app-monorepo x@69a579b，PR #14053 / #14086。
> 测试端：反手：iOS / Android / Desktop / Extension / Web；持仓按钮设置（§3、§5）：仅 iOS / Android
> 变更说明：新增反手确认、真实成交及移动端持仓按钮设置。

## 前置条件
- 测试语言：简体中文；交易用例使用有余额的 HD 钱包，完成 HL Approve Agent，按真实签名、提交、成交及历史记录执行。
- 准备 BTC/ETH 多仓与空仓；每次用例独立记录当前方向、数量、杠杆、保证金模式，交易数量及余额覆盖最小下单要求与手续费。
- 普通成交使用流动性充足市场；部分成交、拒绝、行情异常及异步仓位变化使用测试网或可控环境。
- 移动端配置用例在 iOS / Android 执行；每条配置用例开始前恢复按钮显示，测试后恢复原设置。

## 1. 反手入口与确认

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 多仓 / 空仓反手确认 | 在各端点击目标仓位的「反手」 | 1. 弹窗显示对应资产、当前持仓、反手后持仓、市价单操作及两倍数量、参考价格和预估强平价<br>2. 预览为同数量反向持仓；内容不重叠，确认按钮可点击 |
| P1 | 同账户多资产持仓 | 从 BTC / ETH 对应持仓进入反手确认 | 弹窗资产、数量及方向均对应点击的仓位，不显示另一资产数据 |
| P1 | 关闭确认 | 打开反手确认后点击关闭 | 弹窗关闭；持仓及成交历史无变化 |

## 2. 反手下单与成交

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 多仓 → 同数量空仓 | 记录多仓数量 Q，点击反手并确认，待订单全部成交 | 1. 当前持仓显示空仓，数量 = Q<br>2. 历史成交累计卖出数量 = 2Q，显示平仓与反向开仓的成交结果 |
| ❗️❗️P0❗️❗️ | 空仓 → 同数量多仓 | 记录空仓数量 Q，点击反手并确认，待订单全部成交 | 1. 当前持仓显示多仓，数量 = Q<br>2. 历史成交累计买入数量 = 2Q |
| ❗️❗️P0❗️❗️ | 下单表单已勾只减仓 | 保持普通表单「只减仓」选中，转到持仓点击反手并确认 | 全部成交后显示同数量反向持仓；不在原仓平完后停留为零仓位 |
| P1 | 全仓 / 逐仓、多档杠杆 | 记录全仓 / 逐仓模式和杠杆，分别反手并待全部成交后复核 | 反向持仓数量与原仓相同，沿用原保证金模式及杠杆；资金与成交记录对应实际方向 |
| P1 | 连续两次反手 | 完成第一次反手后，重新打开确认并完成第二次反手 | 第二次使用当前仓位数量；全部成交后方向回到初始方向、数量与第二次确认值相同 |
| P1 | 受理反馈与成交异步 | 在可控环境延迟成交回报，提交反手，先返回受理结果再恢复成交回报 | 确认弹窗在受理后关闭；成交未回报时不提前显示等量反向仓位，回报后按实际成交更新持仓与历史 |

## 3. 移动端持仓按钮设置

> 关闭的操作直接隐藏并自动保存；仅 iOS / Android 支持按钮设置；默认值、全部关闭与跨账户行为见 §5。

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| P1 | 隐藏 / 恢复各操作 | 在移动端分别关闭加仓 / 反手 / 止盈止损 / 平仓中的一个，返回持仓后再开启 | 1. 关闭后仅对应按钮隐藏，其他按钮保留<br>2. 开启后对应按钮恢复且可进入对应流程 |
| P1 | 自动保存与重新进入 / 重启保留 | 修改移动端按钮开关，关闭面板后重进，再退出 Perps 重进及重启 App | 无需保存操作；各次进入的开关状态与持仓按钮显示均保持修改后的设置 |
| P1 | 多个仓位同时应用 | 保留两种资产持仓，关闭反手按钮后查看各仓位 | 两种资产持仓均不显示反手按钮；仓位数量及方向不变 |
| P2 | 多语言、深色模式与窄屏 | 切换中文 / 英文、深色模式及移动端大字体后开关按钮 | 标签可读，开关与按钮不重叠；隐藏项不占用按钮点击区域 |

## 4. 交易保护与成交边界

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 确认前仓位变化 / 已平仓 / 账户切换 | 打开反手确认后，在另一端改变数量、方向、平掉仓位，或切换当前账户，再点击确认 | 显示仓位或账户变化提示；确认不可用或提交被拦截，无新增反手成交 |
| ❗️❗️P0❗️❗️ | 异步准备期间仓位变化 | 点击确认后，在交易准备尚未完成时改变目标仓位 / 账户 | 显示变化提示，当前操作不继续反手；不在新账户下新增成交 |
| P1 | 跳过普通下单确认 | 开启跳过下单确认，再点击反手 | 仍显示反手确认；点击确认前持仓与成交历史无变化 |
| P1 | 数量精度与最小金额边界 | 在可控环境分别准备精度合法、两倍仓位市值为 9.99 / 10 / 10.01 美元的仓位，打开反手确认并提交 | 1. 市价单数量为当前仓位精确两倍，不静默舍入<br>2. 9.99 显示最小金额 $10 提示，不新增成交；10 / 10.01 在保证金充足时可继续提交 |
| P1 | 最大可交易数量与保证金边界 | 记录仓位 Q，在可控环境将可交易上限设为 2Q 加一个数量步长 / 等于 2Q / 少一个数量步长，分别点击确认 | 1. 上限高于 / 等于 2Q 且其他条件满足时可提交<br>2. 上限低于 2Q 时显示「保证金不足」，无本次反手成交；增加可用保证金后可重新确认 |
| P1 | 行情加载失败 | 阻断目标市场行情，打开反手确认后恢复并点击重试 | 1. 缺失行情时价格为占位值，确认不可点击，显示重试入口<br>2. 恢复后显示目标资产价格，确认可点击 |
| P1 | 强平价无法估算 | 在无有效预估强平价的数据下打开确认 | 预估强平价显示占位值，不显示 0、负数或上一仓位价格 |
| P1 | 重复确认及关闭拦截 | 延迟提交响应，连续点击确认，并点击关闭 / 遮罩、按返回 / Esc；恢复响应并待全部成交 | 1. 提交中确认显示加载且不可重复点击，弹窗不能关闭<br>2. 最终为反向 Q，累计成交数量为 2Q，不产生重复反手 |
| P1 | 拒绝或超时后恢复 | 模拟交易被拒 / 超时后确认，再恢复网络重开确认 | 1. 显示错误提示，加载结束，弹窗可关闭<br>2. 重开后按最新持仓准备；先核对历史与仓位，避免未知结果下重复反手 |
| P1 | 部分成交 | 原多仓 Q，控制反手卖单仅成交 0.5Q / Q / 1.5Q / 2Q | 1. 实际持仓分别为多 0.5Q / 零 / 空 0.5Q / 空 Q<br>2. 历史成交与实际持仓对应；不显示为必然等量反向仓位，也不自动追加补单 |
| P1 | 原有挂单与止盈止损 | 保留目标资产的普通挂单及止盈止损后反手 | 客户端不主动撤销原委托；列表按交易所实际保留或取消结果更新，无新增附带止盈止损 |
| P1 | 未启用交易与 HW Agent | 分别使用未启用交易的 HD 账户 / 已启用 Agent 的 HW 账户点击确认 | 1. 未启用账户进入启用交易流程，完成后重新校验仓位<br>2. 已启用 Agent 的 HW 账户由 Agent 签名，不要求设备逐笔确认 |
| P1 | 现货隔离与同名交易资产 | 查看现货持有币种，并从两组同名、不同市场持仓分别打开反手 | 现货不提供反手；确认资产及提交后的持仓属于所点市场 |

## 5. 移动端配置范围与默认状态

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| P1 | 配置入口与默认值 | 在 iOS / Android 清空该测试配置或使用无按钮配置的旧数据，打开布局设置及持仓操作按钮 | 显示加仓 / 反手 / 止盈止损 / 平仓四个开关及当前状态，初始均开启；持仓操作按此顺序显示 |
| P1 | 全部关闭 / 仅保留一个 | 关闭四个按钮，再分别仅开启其中一个 | 全部关闭时不显示操作按钮区；仅开启一个时只显示该按钮，仍可从设置恢复 |
| P1 | 按钮配置与其他设置隔离 | 记录 K 线位置、跳过确认与图表标记状态后开关加仓；再改变 K 线位置并回看按钮配置 | 1. 开关加仓不改变其他设置<br>2. 改变 K 线位置不覆盖已保存的按钮开关 |
| P1 | 本机跨账户与跨设备 | 在移动端账户 A 关闭反手，切换同机账户 B；再在另一台移动设备查看相同账户 | 同机 B 沿用本地显隐设置；另一设备不因该操作同步隐藏 |
| P2 | 隐藏止盈止损后的已有订单 | 保留止盈止损委托后关闭该按钮，再打开历史及恢复显示 | 原委托不因按钮隐藏撤销；恢复后可继续查看或修改原止盈止损 |
