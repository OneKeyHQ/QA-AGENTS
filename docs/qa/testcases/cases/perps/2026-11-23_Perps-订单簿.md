# Perps - 订单簿

> 需求文档：`docs/qa/requirements/Perps-订单簿与市场最近成交.md`
> 规则文档：`docs/qa/rules/perps-rules.md` §16、§18
> 测试端：iOS / Android / Desktop / Web
> Jira Test：[OK-5968](https://onekeyhq.atlassian.net/browse/OK-5968)

## 前置条件

1. 使用包含 OK-66567、OK-67874 和 OK-66568 的 6.8.0 提测构建。准备 BTC、ETH 永续市场、一个有较长资产符号的永续市场及两个现货市场。桌面覆盖宽屏和窄屏，移动端覆盖交易页及全页 K 线。
2. 使用 Hyperliquid 行情或可控数据。分别控制 WebSocket（WS）推送和 HTTP 快照，准备迟到、断线、回补失败及可控时钟。订阅场景通过测试日志观察面板需求，点价时停在下单表单。
3. 固定测试市场、快照和价格档位，准备足够的买卖档位供模式切换。最新成交价用例选择成交价不同于标记价、参考价和盘口中间价的样本。
4. 深度图使用独立盘口快照与累计结果，覆盖永续、DEX 永续和现货的支持入口、稀疏/单侧/空盘口及高低价格精度。Desktop / 大屏 Web 覆盖交易工作区，iOS / Android 覆盖全页行情；Extension 在支持该布局的入口执行。深度图交互只读，不提交交易。

| P1 | 单边盘口切档、行情更新与空档恢复 | 1. 在双边有档位时选择仅买，调整价格档位并推送新双边快照<br>2. 推送仅卖盘的新快照，核对买盘空档并点击可见占位，再切到仅卖。用仅卖开始且后续仅有买盘的数据复测<br>3. 恢复双边报价并切回双边模式 | 1. 保持仅买模式，按当前价格档位显示更新后的买盘<br>2. 空侧显示占位，点击不改变下单价格。有效侧显示该侧新推送的价格和数量<br>3. 两侧恢复并显示当前价格档位的最新盘口 |
| P1 | 实时盘口点价填单 | 1. 在支持点价的交易面板，从市价表单点击双边盘口的一档实时价格<br>2. 分别切到仅买、仅卖，点击该侧展开后新增的一档价格 | 1. 表单切为限价，价格等于该档显示值<br>2. 限价每次等于所点档位的价格，订单仍待用户提交 |
| P1 | 移动交易页点击最新成交价填单 | 1. 在移动交易页保持市价表单和实时盘口。用可控时钟在 WS 成交时间戳距当前 29 秒时点击最新价<br>2. 预填一个不同的限价。分别在仅有 HTTP 成交快照、成交 WS 断线及成交年龄为 30 或 31 秒时点击价格区，期间保持盘口实时。再保持成交有效，分别在盘口仅缓存或过期时复测<br>3. 重连后先仅恢复成交或盘口中的一项并点击价格区，再让两项均实时可用后点击 | 1. 切为限价，填入按交易标的精度处理的最新成交价，订单仍待用户确认提交<br>2. 点击不改变订单类型或已填限价<br>3. 仅一项可用时点击不改表单。两项均实时可用后恢复填价，填入当前成交价 |

## 2. 市场最近成交

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 当前市场公开成交实时展示 | 1. 打开「最近交易」，对照两笔买卖成交的价格、数量和时间<br>2. 推送较新的成交，切换钱包账户后再查看个人历史成交 | 1. 价格保留成交精度，数量列显示当前资产单位，买卖方向和时分秒与同一成交数据一致<br>2. 新成交进入列表顶部。市场列表继续显示当前市场的公开成交，个人历史显示所选账户的成交 |
| ❗️❗️P0❗️❗️ | 快照与推送合并去重及 50 条上限 | 1. 让首屏快照和实时推送包含重复成交、同一毫秒但不同 ID 的成交及乱序记录<br>2. 推送超过 50 条有效记录，让第 49 至 51 条有同毫秒成交，再补发较旧记录 | 1. 同一时间与成交 ID 的记录只显示一次，按成交时间倒序，同一毫秒按成交 ID 从大到小展示<br>2. 仅保留排序后的前 50 条，较旧记录不挤掉最新记录，列表仍可滚动和切换 |
| P1 | 市场切换与迟到响应隔离 | 1. 从 BTC 切到 ETH，延迟 ETH 的首屏响应，查看切换后的列表<br>2. 快速切回 BTC，再释放迟到的 ETH 快照和推送<br>3. 切到现货，再回到永续 | 1. ETH 加载时不显示 BTC 的成交<br>2. 列表只显示 BTC，迟到的 ETH 数据不覆盖当前列表<br>3. 现货无该「最近交易」入口，回到永续后加载所选市场的记录 |
| P1 | 首屏加载、空态与重试 | 1. 让 WS 连通但暂未推送成交，延迟 HTTP 首屏响应，再返回空数据<br>2. 在无记录时分别模拟首屏请求失败、WS 断线，核对中英文提示<br>3. 点击「重试」，延迟响应并尝试再次点击，先返回失败，再恢复数据后重试 | 1. 等待期间显示加载，收到空结果后显示「暂无数据」<br>2. 错误或离线提示与「重试」在列表区域内居中<br>3. 等待时重试按钮显示加载并禁用，失败后恢复可点。恢复后显示当前市场的成交记录 |
| P1 | 断线与回补 | 1. 列表已有有效成交时断开 WS，保持 HTTP 快照可用<br>2. 恢复 WS，同时令 HTTP 回补失败，并让这段时间收到的实时成交少于 50 条<br>3. 恢复 HTTP 后重试，让回补快照与新推送包含重叠成交 | 1. 保留已有成交，列表上方显示离线提示和重试入口<br>2. 已有成交继续可见，回补失败提供重试入口<br>3. 状态提示消失，列表继续更新，重叠成交只显示一次 |
| P1 | 切 Tab、离页及前后台订阅 | 1. Desktop / Web 打开「最近交易」再切回订单簿，分两次在约 10 秒和约 35 秒后返回，核对当前市场的消费需求和成交回补<br>2. 移动端全页 K 线切 Tab、离页或退到后台，再返回核对最近交易 | 1. 30 秒内沿用最近交易的 50 条消费需求，列表持续接收更新。超过 30 秒释放该需求，返回后重新申请并回补。最新价仍使用行情时可共用现有 WS 连接<br>2. 页内切换保留最近交易需求，离页或退后台时释放，返回后恢复当前市场的更新 |
| P1 | 成交时间和浏览器跳转 | 1. 点击时间文本，再点击普通成交旁的浏览器图标<br>2. 点击零哈希成交的图标，另查看无有效哈希的成交 | 1. 点击时间文字不跳转，图标打开 Hyperliquid 浏览器的成交详情路径，地址以该笔成交哈希结尾<br>2. 零哈希沿用该跳转路径并保留零哈希值，无有效哈希时不显示跳转入口。TWAP 或清算说明在浏览器落地页单独核对 |
| P1 | 窄屏和长语言下的标签及列头 | 1. 在窄屏 Desktop / Web 选择较长文案语言和长资产符号，查看并悬停两个 Tab 和数量列头<br>2. 在 iOS / Android 全页行情点击数量列头 | 1. Tab 和列头可辨认，数量列显示当前资产符号，时间与浏览器图标互不遮挡。Tab 和数量列头不弹出重复提示<br>2. 数量列头弹层显示包含当前资产符号的完整标题 |

## 3. 深度图与累计挂单

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 当前市场有可独立核对的买卖盘口 | 1. 打开深度图，对照同一快照逐档价格及累计挂单数量<br>2. 分别只更新价格、只更新数量，切永续 / 现货 / DEX 永续复测 | 1. 横轴为价格，纵轴为累计数量，买卖两侧颜色与盘口方向一致，单位和精度对应当前市场<br>2. 每侧沿该侧价格方向累计，曲线及读数与同快照独立结果一致，更新后不保留旧累计量 |
| P1 | 深度图有多个价位，部分靠近容器边缘 | 1. Desktop / Web 悬停、iOS / Android 长按两侧不同价位，移动到边缘及买卖价差内<br>2. 退出手势，再用单个有效价位的盘口复测 | 1. 提示显示对应真实价位和累计数量，边缘提示不被容器裁切<br>2. 价差内不显示虚构挂单，单价位读数可辨识，退出后提示不拦截其他操作 |
| P1 | 已记录当前深度图范围，数据可控制 | 1. 在支持缩放的入口缩放价格范围，再减少远端档位、拉大价差并恢复数据<br>2. 切到价格量级不同的市场，再切回 | 1. 曲线和坐标保持可读，不把未观测范围画成额外挂单深度<br>2. 范围及读数属于当前市场，不沿用上一市场的价格和数量 |
| P1 | 分别准备仅买、仅卖、两侧空、异常价格或数量的盘口 | 1. 依次加载各组快照，再恢复双边有效盘口<br>2. 在切换中快速更换市场并放行旧响应 | 1. 有效侧继续显示，空侧和无数据状态可辨识，异常值不生成误导曲线或引发崩溃<br>2. 仅显示当前市场有效数据，恢复后两侧及坐标更新 |
| P1 | 深度图已加载，网络及后台状态可控制 | 1. 断开行情并切后台，再恢复；延迟恢复后的第一个新盘口<br>2. 切订单簿后分别在 10 秒和 65 秒返回深度图，再离页并重进 | 1. 中断期间可识别数据失效，不将旧图当作实时可交互数据；新盘口到达后恢复当前市场<br>2. 短时切换可沿用保温数据，超过保温期重新获取；离页、后台和反复切换不累积重复订阅 |
| P1 | Desktop / 大屏 Web 工作区正在显示深度图 | 1. 打开存款 / 设置弹窗并保持片刻，再关闭<br>2. 关闭时延迟或令首个新盘口获取失败，随后恢复行情 | 1. 弹窗后方保留已有深度图，不突然清空<br>2. 恢复前图表不使用旧快照继续交互，失败状态可识别；收到当前市场新盘口后恢复 |
| P1 | 宽窄屏、长资产名和中英文环境，深度图持续收行情 | 1. 调整支持入口的可用宽度，持续移动提示并切订单簿和最近交易<br>2. 重复进出 10 轮，操作下单表单但不提交 | 1. 坐标、单位、提示及切换入口可见可用，不遮挡交易输入<br>2. 其他市场面板持续可操作，退出后旧提示消失，记录请求数、订阅与内存以检查累积增长 |
