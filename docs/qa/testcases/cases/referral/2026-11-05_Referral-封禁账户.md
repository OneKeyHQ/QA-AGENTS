# 返佣 - 封禁账户

> 更新日期：2026-11-06
> 测试端：iOS / Android / Extension / Desktop / Web
> 规则文档：`docs/qa/rules/referral-rules.md`
> 需求文档：`docs/qa/requirements/Referral-封禁账户.md`
> 需求来源：Jira Test OK-27650；2026-11-05 用户确认返佣差异清单并授权补充、review 与同步。

## 前置条件

1. 仅在测试环境准备可 Suspend/Unsuspend 的 OneKey ID、主邀请码、子邀请码，以及有绑定关系的受邀钱包。
2. 准备封禁前已存在的 DeFi、Perps、Swap 和硬件佣金记录；另备未受封禁影响的对照账号。
3. 封禁操作由测试后台应用，记录封禁/解封时间用于划分奖励归属；本次不实际操作后台。

## 1. 封禁提示与客服

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 已登录且被 Suspend 的邀请人 | 重新进入或刷新邀请奖励首页 | 显示账户异常 banner 与联系客服入口 |
| P1 | 封禁 banner 可见 | 点击联系客服后返回首页 | 跳转至客服入口；返回后 banner 仍显示，封禁状态不改变 |
| P1 | 封禁后重新登录 / 多端访问 | 使用同一测试 ID 打开邀请奖励 | 各端显示该账号的异常状态，不显示对照账号信息 |

## 2. 主邀请码与子邀请码失效

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 账号已封禁，主邀请码 / 子邀请码尚未使用 | 在测试商店输入对应码 | 显示邀请码不存在或不可用提示，不建立新优惠/返佣关系 |
| ❗️❗️P0❗️❗️ | 账号已封禁，受邀钱包尚未绑定 | 分别用主码 / 子码提交绑定 | 显示邀请码不存在或不可用提示；钱包仍未绑定，不进入已绑定状态 |
| P1 | 封禁前已复制的硬件 / Perps / DeFi / Swap 邀请链接 | 打开链接并提交原邀请码 | 不能绕过封禁完成新的邀请绑定；已有落地页不意味着码可用 |
| P1 | 封禁账号和未封禁对照账号各有码 | 分别提交两类邀请码 | 封禁码不可用；对照码仍可绑定或按当前商店活动使用 |

## 3. 封禁期间奖励与受邀者权益

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 封禁后受邀钱包继续产生 DeFi / Perps 收益 | 按封禁时间分段核对邀请人奖励 | 封禁后不再新增该邀请人的 DeFi / Perps 佣金；封禁前已记账记录仍可查看 |
| ❗️❗️P0❗️❗️ | 封禁邀请人的既有受邀钱包有自身奖励 | 打开受邀钱包的福利页与合约 / Swap / DeFi 明细 | 受邀者自身奖励继续按规则计算；不因邀请人封禁而清空或停算 |
| P1 | 账号有封禁前硬件订单及发放历史 | 查看硬件详情和奖励历史 | 既有订单、金额与发放历史仍可查看；不把封禁当作订单退款 |
| P1 | 封禁 / 解封期间反复刷新与切账户 | 对照封禁时间点核对记录 | 不因重复刷新重复记账；各账号记录与状态隔离 |

## 4. 解封后恢复

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 后台已 Unsuspend | 刷新邀请奖励首页 | 账户异常 banner 不再显示；原账号、邀请码与既有记录保留 |
| ❗️❗️P0❗️❗️ | 解封后的主码 / 子码 | 用新测试钱包绑定，并在测试商店验证对应码 | 邀请码可用于新绑定和当前商店活动；显示对应邀请关系 |
| ❗️❗️P0❗️❗️ | 解封后继续产生 DeFi / Perps 收益 | 按解封时间分段核对邀请人奖励 | 解封后的新佣金继续累计；封禁期间停算部分不重复计入 |
| P1 | 既有受邀者在解封前后均有奖励 | 对比福利页奖励和历史 | 自身奖励持续保留，解封不重置受邀者累计和历史 |
| P1 | 恢复后再次封禁同一账号 | 重复封禁/解封流程后刷新 | banner、码可用状态与当前后台状态一致；不产生重复邀请关系 |

## 5. Swap 封禁与福利身份隔离

Swap 沿用 Perps 的封禁与解封规则；OneKey ID 的邀请人身份与当前钱包的受邀者身份分别核对。

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| P1 | 封禁邀请人下有 Swap 佣金，既有受邀钱包继续交易 | 1. 按封禁时间核对两侧奖励<br>2. 解封后产生新交易并再次核对 | 1. 封禁期间不新增邀请人 Swap 佣金，封禁前记录保留<br>2. 既有受邀钱包的 Swap 奖励持续计算<br>3. 解封后邀请人新佣金恢复累计，封禁期间停算部分不补计 |
| P1 | 已封禁 ID，当前钱包作为受邀者有奖励 | 1. 从邀请奖励切换福利页<br>2. 退出 ID 后再次查看福利页<br>3. 切换至奖励不同的钱包再返回 | 1. 邀请奖励显示该 ID 的异常提示，福利页显示当前钱包的受邀者奖励<br>2. 退出 ID 后仍可查看当前钱包奖励，邀请人佣金不可见<br>3. 切换后仅显示所选钱包的奖励，返回后显示原钱包奖励 |
