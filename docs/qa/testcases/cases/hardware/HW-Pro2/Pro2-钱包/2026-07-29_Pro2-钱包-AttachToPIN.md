# Pro2 - 钱包 AttachToPIN（关联 PIN）

> 规则文档：`docs/qa/rules/hardware-rules.md`（§3.3 Attach to PIN）+ §14.9（我的地址 Extra PIN 联动）
> 需求文档：`docs/qa/requirements/Hardware-Pro2关联PIN.md`
> 测试端：Pro2 设备端为主（长度 / 组数上限含 Classic / 1S 差异，场景内注明）
> 变更说明：首版——覆盖关联（新增）/ 更新 / 删除三条主流程、绑定后解锁与地址验证、修改 PIN 码覆盖矩阵、组数上限与锁定规则、防时序侧信道
> 2026-07-29 修订：经产品确认，进入关联流程时**任何会话（主 PIN / Passphrase PIN 解锁）均需通过主 PIN 校验**；Passphrase PIN 会话下需要主 PIN 的场景显示「标准钱包 PIN」副标题，主 PIN 会话无副标题；删除原「主 PIN 会话免验证」预期
> 2026-07-29 修订 2：新增「设备差异对照表」（Classic 1S / Pro / Pro2）；绑定确认链路按设备拆分（Pro2 点击「继续」/ 右上角关闭按钮 / 弹窗提示替代独立提示页）；删除流程补全二次确认页与删除成功提示页

## 前置条件与测试数据

1. Pro2 已完成初始化（标准钱包已创建、主 PIN 已设置，下文记作**主 PIN**）
2. Passphrase 开关已开启，「钱包 → Passphrase」页面显示「关联PIN」入口
3. 测试 Passphrase PIN 记号：**A / B / C Pass_pin**（互不相同、均与主 PIN 不同，各自绑定不同 Passphrase）；§5 修改 PIN 码矩阵执行前需已绑定 A / B / C 三组
4. 全设备一致的边界参数：Passphrase PIN 最少 **6 位**；Passphrase 内容最长 **50 字符**；其余差异见下方「设备差异对照表」
5. ⚠️ 破坏性用例（输错主 PIN 5 次设备重置）安排在本轮**最后**执行，执行前确认助记词已备份、设备数据可重建

| 确认 Passphrase 后链路 | 独立提示页面：提示保存 Passphrase →「我明白」→ loading → 绑定成功页 | 同 1S | **无独立提示页面**：弹窗提示（此时已绑定成功）→「我已了解」→ 绑定成功页 |

## 6. 修改 PIN 码矩阵（前置：已绑定 A / B / C 三组 Passphrase PIN）

> 均通过「修改 PIN 码」入口执行；「以 X 解锁」指锁屏后用 X 解锁再进入修改流程。

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | A Pass_pin → 新 PIN（未被使用） | 1. 以 A Pass_pin 解锁进入修改 PIN 码<br>2. 修改为未被使用的新 PIN | 新 PIN 可解锁，**旧 PIN 失效** |
| ❗️❗️P0❗️❗️ | B Pass_pin → 新 PIN（未被使用） | 1. 以 B Pass_pin 解锁进入修改 PIN 码<br>2. 修改为未被使用的新 PIN | 新 PIN 可解锁，旧 PIN 失效 |
| ❗️❗️P0❗️❗️ | A Pass_pin → C Pass_pin（占用已存在值） | 1. 以 A Pass_pin 解锁进入修改 PIN 码<br>2. 修改为 C Pass_pin 的值 | 1. 提示**覆盖**，可取消<br>2. 点击「覆盖」后修改生效<br>3. Pro / Pro2 查看「我的地址」（1S 在 App 核对）当前仍为 **A Pass_pin 钱包**，旧 PIN 失效（C 原绑定被覆盖） |
| ❗️❗️P0❗️❗️ | B Pass_pin → A Pass_pin（占用已存在值） | 1. 以 B Pass_pin 解锁进入修改 PIN 码<br>2. 修改为 A Pass_pin 的值 | 1. 提示覆盖，可取消；点击「覆盖」后修改生效<br>2. **设备不锁定**，当前为 **B Pass_pin 钱包**，旧 PIN 失效 |
| ❗️❗️P0❗️❗️ | 主 PIN → A Pass_pin（主 PIN 占用 Passphrase PIN 值） | 1. 以主 PIN 解锁进入修改 PIN 码<br>2. 修改为 A Pass_pin 的值 | 1. 提示覆盖，可取消；点击「覆盖」后修改生效<br>2. 设备不锁定，当前为**主钱包**，旧主 PIN 失效 |
| ❗️❗️P0❗️❗️ | 主 PIN 释放后旧值可复用 | 1. 先将主 PIN 修改为新 PIN<br>2. 再将 A Pass_pin 修改为**之前的主 PIN** | 两次均**不提示覆盖**，修改生效；两个旧 PIN 均失效 |
| ❗️❗️P0❗️❗️ | 两组 Pass_pin 先后改为同值 | 1. 先将 A Pass_pin 修改为新 PIN<br>2. 再以 B Pass_pin 解锁，将 B Pass_pin 修改为**同样的新 PIN** | 1. 第二次修改提示覆盖，可取消；点击「覆盖」后修改生效<br>2. 设备不锁定，当前为 **B Pass_pin 钱包**，旧 PIN 失效（A 的新绑定被覆盖） |

## 7. 数量上限与移除

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 与主 PIN 一致拦截 | 1. 设置 / 修改 Passphrase PIN 时输入与主 PIN 相同的值 | 提示 **PIN 已被使用** |
| P1 | 满上限修改已存在 PIN | 1. 绑定数达上限（Pro / Pro2 30 组，1S 3 组）<br>2. 设置流程输入已存在的 Passphrase PIN | 进入**更新 / 删除**流程，不受上限限制 |
| ❗️❗️P0❗️❗️ | 满上限新增拦截 | 1. 绑定数达上限时设置流程输入**新** PIN | 提示已达上限，提供「**管理**」/「**关闭**」（1S / Pro 为「移除」/「关闭」） |
| ❗️❗️P0❗️❗️ | 上限弹窗关闭 | 1. 点击「关闭」 | 返回 Passphrase 页面 |
| ❗️❗️P0❗️❗️ | 移除需正确 Passphrase PIN | 1. 点击「管理」（1S / Pro 点击「移除」）<br>2. 依次输入：错误的 Passphrase PIN / 主 PIN / 正确的 Passphrase PIN | 1. 错误 Passphrase PIN → 提示**输入的 PIN 不正确**<br>2. 主 PIN → 提示输入的 PIN 不正确<br>3. 正确 Passphrase PIN → 进入删除流程 |
| P1 | 解锁耗时无差别（防时序侧信道） | 1. 满上限后锁定设备<br>2. 分别用主 PIN / 第 1 组 / 第 15 组 / 第 30 组（Pro / Pro2；1S 用第 1 / 2 / 3 组）/ 错误 Passphrase PIN 解锁 | 各次解锁（含错误 PIN 判定）耗时**无明显区别** |

## 8. 锁定规则

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 主 PIN 会话操作不锁定 | 1. 主 PIN 解锁<br>2. 删除或修改任意 Passphrase PIN | 操作完成，设备**不锁定** |
| ❗️❗️P0❗️❗️ | Passphrase 会话操作非当前 PIN | 1. 以 A Pass_pin 解锁<br>2. 删除或修改 B Pass_pin | 操作完成，设备**不锁定**，仍为 A Pass_pin 钱包会话 |
| ❗️❗️P0❗️❗️ | Passphrase 会话操作当前 PIN | 1. 以 A Pass_pin 解锁<br>2. 删除或修改 A Pass_pin 自身 | 操作完成后设备**锁定** |
| ❗️❗️P0❗️❗️ | Passphrase 会话关闭开关 | 1. 以 Passphrase PIN 解锁<br>2. 关闭 Passphrase 开关<br>3. 分别尝试用各 Passphrase PIN、主 PIN 解锁 | 1. 设备**锁定**<br>2. 所有 Passphrase PIN（Attach to PIN）**无法解锁**<br>3. 主 PIN 可解锁，Passphrase 开关已为**关闭**状态 |
