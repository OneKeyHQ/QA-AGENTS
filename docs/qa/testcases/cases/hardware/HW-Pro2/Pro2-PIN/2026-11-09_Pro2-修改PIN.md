# Pro2 - 修改PIN

> 规则文档：docs/qa/rules/hardware-rules.md
> 需求文档：docs/qa/requirements/Hardware-Pro2专项用例补齐.md
> 测试端：Pro2 设备端；按本份前置条件配合 iOS / Android / Desktop / Extension / Web。
> Jira 对应：OK-54257；同步字段：description。

## 前置条件

1. Pro2 已激活，使用已备份的专用测试钱包；重置、断电或输错 PIN 场景使用独立设备状态。
2. 初始主 PIN 为 4 位；另准备 50 位新 PIN。关联 PIN 的覆盖与钱包身份详测复用已有 Attach to PIN 用例。

## 1. 修改与取消

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 相同/短转长/长转短/50 位 | 依次把主 PIN 改为原值、较长值、4 位值、50 位值；每次锁屏后用当前值解锁 | 每次显示更改完成；当前 PIN 可解锁，已被替换的旧 PIN 不解锁；改为相同值时仍可解锁 |
| P1 | 两次新 PIN 不一致 | 输入正确原 PIN，两次新 PIN 输入不同值，按引导重新输入一致值 | 显示两次 PIN 不一致，本次未写入；重新设置后仅一致的新值生效 |
| P1 | 取消与返回 | 分别在更改提示、原 PIN、新 PIN、确认新 PIN 阶段取消/返回，随后锁屏验证原 PIN | 退出至安全页，未提交的值不生效；原 PIN 可解锁 |
| P1 | 提交时断电 | 提交最后一步同时断电，重启后验证新旧 PIN | 仅完整旧值或完整新值生效；不会出现两个值均无法解锁或截断的 PIN |

## 2. 共享错误计数

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| P1 | 原 PIN 输错后锁定 | 更改 PIN 时输错一次原 PIN，等自动锁定，再进入解锁 | 显示剩余 4 次；锁定不恢复次数，正确 PIN 解锁后可再次更改 |
