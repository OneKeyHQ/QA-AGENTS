# Hardware - 蓝牙配对-设备未激活

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android（蓝牙）
> Jira 对应：OK-24610；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo；Mini 不支持蓝牙，不执行蓝牙部分。
2. iOS、Android分别执行，使用未初始化专用设备；取消旧配对记录并准备创建、导入两条初始化路线。
3. Pro必须完成初始化后才能配对；其他蓝牙型号可在初始化完成前配对，不沿用旧文档“所有设备均需初始化完成”的统括预期。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | Pro初始化完成前 | 在Pro语言、PIN、助记词等未完成阶段由App发起蓝牙配对 | 不能完成配对，提示需先完成初始化；App不提前添加可用钱包 |
| ❗️❗️P0❗️❗️ | 其他型号初始化前配对 | 除Pro外，逐个支持蓝牙型号在未完成初始化时由App发起配对，按该型号确认方式完成 | 可建立蓝牙配对；配对完成不等于初始化完成，App仍按设备进度引导 |
| P1 | Pro创建完成后配对 | 在Pro完成创建或导入至钱包就绪阶段，再由App发起并完成配对 | 可建立蓝牙配对，完成后按设备进度继续引导及钱包添加 |
| P1 | 初始化中取消配对再重试 | 在未初始化设备的可配对阶段取消，再重新发起配对并完成初始化 | 双方退出旧配对流程；重试后可连接，设备初始化进度不因配对取消被误标完成 |
