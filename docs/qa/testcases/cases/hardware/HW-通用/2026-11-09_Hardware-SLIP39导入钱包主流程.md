# Hardware - SLIP39导入钱包主流程

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：设备端 / Desktop（App及离线参考核对）
> Jira 对应：OK-54832；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Pro，沿用原Jira支持范围。
2. 从OK-54832末尾保留的原测试数据表准备全部五组：20词1份/阈值1、3份/阈值2、16份/阈值16；33词1份/阈值1、3份/阈值2。份额内容仅在授权测试环境使用，不复制进仓库。
3. 逐组登记标准钱包及onekey密语钱包的完整预期地址，按原Jira数据逐项核对；每组重置专用测试设备后执行。
4. 准备Desktop App、独立离线参考及https://hardware-example.onekeytest.com/expo-example/slip39-test；仅对授权测试余额做小额交互。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 20词三组完整恢复 | 分别导入20词三组数据，按阈值输入1、2、16份有效且不同的份额，完成PIN及引导 | 达到阈值后进入钱包就绪；各组标准地址与该组原Jira参考逐字符一致 |
| ❗️❗️P0❗️❗️ | 33词两组完整恢复 | 分别导入33词两组数据，按阈值输入1、2份有效且不同份额，完成引导 | 两组分别恢复，标准地址与对应参考一致；不将33词的3份/阈值2误写为阈值3 |
| P1 | 不足阈值再补足 | 在3份/阈值2及16份/阈值16组分别停在少一份的位置，查看提示，再补入剩余有效份额 | 不足阈值时不完成恢复，显示剩余份额需求；补足后才进入钱包就绪 |
| P1 | 重复或不属于同组的份额 | 在多份恢复中输入重复份额及另一组份额，再改回本组未使用份额 | 重复或其他组份额不计入本组有效份数；改用有效不同份额后可继续恢复 |
| P1 | 标准与隐藏钱包及公钥 | 对五组恢复钱包分别核对标准与onekey密语地址，再执行批量地址、变种路径和公钥核对 | 地址、公钥与每组固定参考一致；标准与隐藏钱包各自隔离，不跨组混用 |
| P1 | 恢复后的备份与核对入口 | 每组恢复后查看备份、核对助记词入口 | SeedCard及Keytag备份不可用；核对助记词仅显示20词、33词选项 |
| P1 | 取消恢复后重新输入 | 恢复达到阈值前取消，再重新输入选定组的完整有效份额 | 取消不产生已恢复钱包；重新恢复地址与选定组一致，旧轮次份数不累加 |
