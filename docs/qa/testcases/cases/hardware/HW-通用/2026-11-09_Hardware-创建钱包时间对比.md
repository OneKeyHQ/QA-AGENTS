# Hardware - 创建钱包时间对比

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android / Desktop / Extension / Web（按本份适用通道及第三方钱包范围执行）
> Jira 对应：OK-19779；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Mini / Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo，按各型号已支持的功能及受测端连接方式执行。
2. 固定同一设备、账户、网络和主机；登记旧/新App与固件版本，测试前清理App侧测试钱包记录。
3. 分别覆盖USB及支持的蓝牙；每组至少3次，开始点为确认添加设备钱包，结束点为钱包首页可查看默认账户。
4. 首次与已配对连接分开记录；PIN及人工确认停顿单独计时，不把不同设备或网络条件混为同组。
5. Classic沿用原Jira的Classic 3.0.0指标：USB、蓝牙均为V4约12–17秒、V5约20秒；保留原V4/V5分组，不将近似值改成精确超时阈值。指标来源：https://onekeyhq.atlassian.net/wiki/spaces/ONEKEY/pages/169410644。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| P1 | 同机新旧版本创建耗时 | 按相同起止点分别执行旧、新版本各3次，逐次记录总耗时、人工等待及失败次数 | 1. Classic按原指标对照：USB、蓝牙在V4约12–17秒，V5约20秒，记录各轮与参考值的差异<br>2. 其他型号只记录每组中位数、最大值及失败次数，不套用Classic秒数 |
| P1 | USB与蓝牙对照 | 在同一设备、版本和账户条件下分别记录USB及蓝牙创建耗时，Mini只记录USB | 两种通道分别输出记录；Mini蓝牙标记不适用，不计为失败或完成 |
| P1 | 创建完成的地址及数量 | 每次计时结束后核对钱包列表与默认账户，再移除本次App测试记录继续下一轮 | 每轮仅增加一份目标设备钱包，默认账户可查看且地址一致；超时、失败及重试轮次保留原始记录 |
