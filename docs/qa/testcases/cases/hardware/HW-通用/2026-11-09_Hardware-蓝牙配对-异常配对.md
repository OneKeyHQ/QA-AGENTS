# Hardware - 蓝牙配对-异常配对

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android（蓝牙）
> Jira 对应：OK-24612；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo；Mini 不支持蓝牙，不执行蓝牙部分。
2. iOS、Android分别执行并清除旧配对记录；准备配对确认页面及可控取消、超时场景。
3. 错误配对码、关闭配对码页仅适用要求输入配对码的旧型号；Pro/Pro2不执行输入配对码步骤，其他型号按本轮实际确认方式登记。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 错误配对码 | 在要求配对码的型号输入与设备不同的配对码 | 配对失败，双方不显示已连接；返回搜索后可重新发起 |
| P1 | 旧型号关闭配对码页 | 在旧型号主动关闭设备配对码页面，再在手机输入本轮记下的有效配对码 | 已发起的有效配对可继续完成，不因配对码页关闭留下无法退出的流程 |
| P1 | 手机端取消 | 由手机取消本轮配对，再重新发起并完成设备确认 | 本轮双方显示已取消或退出配对，重试后可建立连接 |
| P1 | 设备端取消 | 在设备取消本轮配对，再从手机重新发起 | 手机不显示配对已完成，双方退出本轮流程；重试可连接 |
| P1 | 配对超时 | 保持本轮配对未确认至超时，再重新发起 | 本轮提示超时/配对失败并退出；重试可连接，旧用例约30秒仅作观测记录，不作为所有型号统一硬阈值 |
