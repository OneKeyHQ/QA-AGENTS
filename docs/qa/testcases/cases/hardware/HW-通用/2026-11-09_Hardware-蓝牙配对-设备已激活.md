# Hardware - 蓝牙配对-设备已激活

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android（蓝牙，USB打断使用Desktop辅助）
> Jira 对应：OK-24611；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo；Mini 不支持蓝牙，不执行蓝牙部分。
2. iOS、Android分别执行，设备已初始化；分别准备解锁、锁定、无旧配对记录状态。
3. Pro先解锁再配对；其他型号允许先配对，但访问钱包仍须通过该型号的解锁验证。Pro/Pro2不要求输入配对码。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 已解锁设备配对 | 设备停在首页，App发起连接并按设备确认方式完成配对、添加钱包 | App与设备均显示已连接，添加账户地址与目标设备一致 |
| P1 | 锁定设备配对顺序 | 锁定设备后发起配对；Pro先输入PIN，其他型号按自身配对流程继续，再请求地址 | Pro解锁后继续配对；其他型号不因先配对绕过钱包解锁，解锁后才显示所请求地址 |
| P1 | 取消后再次配对 | 在配对页面分别取消，再从App重新搜索并配对 | 双方退出旧配对页；重新配对可完成，不残留不可关闭弹窗 |
| P1 | USB流程中发起配对 | 分别在USB交易确认、PIN输入、连接钱包步骤发起蓝牙配对；PIN输入先完成，Pro2保留USB优先差异 | 其他适用型号结束或打断可中断请求后展示本次配对；PIN未完成不被绕过；Pro2不以蓝牙替换未结束USB请求 |
| P1 | Boot模式后回固件模式 | 在Boot模式从App发起蓝牙配对，再退出Boot进入固件模式重新发起 | Boot模式不完成蓝牙配对；回到固件模式后可按设备确认方式配对 |
