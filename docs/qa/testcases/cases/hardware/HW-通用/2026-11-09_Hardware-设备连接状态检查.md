# Hardware - 设备连接状态检查

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android / Desktop / Extension / Web（按本份适用通道及第三方钱包范围执行）
> Jira 对应：OK-20154；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Mini / Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo，按各型号已支持的功能及受测端连接方式执行。
2. 仅Mini不支持蓝牙；其他型号分别验证蓝牙连接、断开、关闭状态。记录各型号提供的USB、蓝牙与AirGap开关。
3. Pro/Pro2核对钱包设置中USB、蓝牙默认开启及AirGap默认关闭；Neo不显示AirGap开关。
4. 准备USB供电线、可控蓝牙主机及充电状态；设备图标按本型号资源核对，不跨型号硬套图样。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | USB与蓝牙连接图标 | 分别建立、断开USB及蓝牙连接，具有蓝牙开关的设备再关闭蓝牙 | 图标逐次对应已连接、断开或关闭状态；Mini不显示蓝牙已连接状态 |
| P1 | 充电状态 | 分别接入与拔出供电线，观察USB通信及充电图标 | 供电时显示本型号充电状态，拔线后退出充电状态；只充电不被误显示为USB钱包已连接 |
| P1 | 关闭蓝牙后Boot及固件模式 | 在具有蓝牙开关的型号关闭蓝牙，搜索设备，再切Boot及回固件模式观察 | 关闭时不能被蓝牙搜索及配对；状态与开关一致，不在Boot中误显示已配对 |
| P1 | 关闭USB后Boot模式 | 在具有USB开关的型号关闭USB并接线，确认仅供电，再进入Boot模式连接 | 固件模式不可通过USB钱包通信且保留充电；Boot模式仍可通过USB被识别 |
| P1 | Pro/Pro2开关及Neo差异 | 在Pro/Pro2核对默认USB、蓝牙和AirGap开关，再查看Neo设置 | Pro/Pro2默认USB、蓝牙开启且AirGap关闭；Neo不显示AirGap开关 |
| P1 | AirGap互斥状态 | 在支持AirGap的型号开启后查看USB、蓝牙开关，再关闭AirGap | 开启时USB和蓝牙关闭且不可点击；关闭后恢复开启，连接禁用与恢复详测复用已有专项 |
