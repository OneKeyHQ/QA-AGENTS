# Hardware - 新旧版本兼容测试

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android / Desktop（按钱包与通道支持范围执行）
> Jira 对应：OK-27684；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Mini / Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo，按各型号已支持的功能及受测端连接方式执行。
2. 登记同型号旧/新系统固件、蓝牙固件及线上/待发布OneKey App版本；准备可重复恢复的专用钱包。
3. iOS、Android覆盖蓝牙；USB仅在受测端支持时执行，Mini只执行USB；OKX仅执行已验证兼容型号，原用例排除Pro2。
4. 准备可控地址及小额测试交易；升级前记录钱包指纹、地址和设备信息。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 已有钱包升级后继续通信 | 1. 分别用线上、待发布OneKey App连接旧固件设备并添加钱包，按支持通道覆盖USB与蓝牙<br>2. 通过受支持流程升级固件，重新连接并核对原账户地址、发起小额测试交易 | 1. 升级后仍识别原设备、原钱包和原地址<br>2. 地址核对与交易签名均可完成，交易仅广播一次 |
| P1 | 升级后首次配对 | 清除手机与测试设备的旧配对记录，升级后分别用OneKey、OKX在各自兼容型号及iOS、Android首次配对、添加账户，再核对地址并签署一笔小额测试交易 | 1. 两个App分别在其兼容型号完成首次配对并进入对应钱包，地址与原参考一致，无重复钱包记录<br>2. 首次配对后的交易须经设备明确确认，链上仅一笔本次测试交易 |
| P1 | 取消后重新配对 | 首次配对时取消，再重新发起配对并核对地址 | 取消后双方退出本次配对；重新配对后设备显示本次请求地址 |
| P1 | OKX兼容型号升级前后 | 在已兼容型号用OKX连接旧固件，完成受支持的固件升级后重连并核对地址、签署测试交易 | 旧账户地址与升级前一致，升级后可再次连接和签名，不把不兼容型号计为通过 |
