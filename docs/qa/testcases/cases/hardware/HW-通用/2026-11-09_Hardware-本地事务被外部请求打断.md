# Hardware - 本地事务被外部请求打断

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android / Desktop / Extension / Web（按本份适用通道及第三方钱包范围执行）
> Jira 对应：OK-24214；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Classic / Classic 1S / Classic Pure（Pure）/ Touch / Pro / Pro2 / Neo；Mini 不支持蓝牙，不执行蓝牙部分。
2. 设备已激活并停留设置一级、二级或更深普通页面；准备手机蓝牙及Desktop USB地址核对请求。
3. 仅打断可退出的普通本地页；PIN、备份等受保护步骤保留其保护，不以外部请求绕过验证。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | 蓝牙配对打断设置页 | 在普通设置页从手机发起蓝牙配对，明确完成或取消后再次操作设备 | 1. 配对界面完整展示；Touch、Classic不先返回首页，原本地页不闪退<br>2. 配对结束后本地操作仍可继续，旧触摸不确认新请求 |
| P1 | USB请求打断旧型号本地页 | 在Touch、Classic的普通设置子页由USB发起地址核对 | 本地页退出至首页后展示USB地址请求，地址与本次输入一致 |
| P1 | Pro2请求打断不回首页 | 在Pro2普通设置子页由USB发起地址核对 | 直接展示新地址请求，不先跳回首页；处理请求后页面可继续操作 |
| P1 | 打断后重新进入原页 | 分别处理蓝牙、USB插入请求，再回到原设置页点击、滚动或返回 | 页面完整可操作，无半程位移、叠页、闪烁或触摸失效 |
