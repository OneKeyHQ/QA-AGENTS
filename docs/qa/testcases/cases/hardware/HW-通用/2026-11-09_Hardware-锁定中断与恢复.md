# Hardware - 锁定中断与恢复

> 规则文档：docs/qa/rules/hardware-rules.md（§19）
> 需求文档：docs/qa/requirements/Hardware-通用专项用例补齐.md
> 测试端：iOS / Android / Desktop / Extension / Web（按本份适用通道及第三方钱包范围执行）
> Jira 对应：OK-9513；仅同步description，保留未授权修改的字段。

## 前置条件

1. 适用设备：Touch / Pro；USB锁相关步骤只在具备相应开关的型号执行。
2. 准备已激活设备、可控地址和小额测试交易；按受测型号开启USB锁与自动锁定，并记录原设置。
3. 中断时交易尚未确认、未广播；测试完成恢复原锁定设置。

## 1. 用例内容

| 优先级 | 场景 | 操作步骤 | 预期结果 |
| --- | --- | --- | --- |
| ❗️❗️P0❗️❗️ | USB锁打断蓝牙请求 | 开启USB锁，通过蓝牙进入待确认交互页，插拔USB | 设备锁定并结束本次蓝牙交互，App收到取消/中断结果；待签名交易未广播 |
| P1 | 自动锁定打断请求 | 分别在地址核对、交易确认页停止触摸，等待自动锁定 | 锁定后本次请求返回取消，App不继续等待或显示交易已确认 |
| P1 | 断开后解锁重发 | 在USB签名确认页拔线，再接回、解锁并重新发起本次交易 | 旧请求不自动恢复为已签名；重发经明确确认后仅广播一笔交易 |
