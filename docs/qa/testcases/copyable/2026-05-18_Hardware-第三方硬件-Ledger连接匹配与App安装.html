前置条件

- 已安装可用版本 OneKey App（Desktop），测试账号具备新增 wallet/account 所需权限。

- 至少准备 2 台 Ledger 设备（覆盖同助记词/不同助记词组合）。

- 准备 1 台可通过蓝牙发现的 Ledger 设备，Desktop 已开启蓝牙权限，用于 BLE 分支验证；准备可用于校验的网络：BTC、EVM、SOL、TRON。

- 准备 1 台可清空或控制已安装 App 状态的 Ledger 设备，用于验证“全未安装”“部分已安装”“单网络未安装”分支。

1. Ledger（已沉淀）

> 连接支持网络：BTC / EVM / SOL / TRON。

> 安装能力支持网络：BTC / ETH / TRX / SOL。

> 命名口径：安装能力按 App 名称使用 ETH / TRX；账户交互回归按网络类别使用 EVM / TRON。

1.1 USB 设备识别与连接

优先级场景操作步骤预期结果
❗️❗️P0❗️❗️两台 Ledger（A、B）同时 USB 接入1. 启动 App
2. 进入连接 Ledger 流程
3. 发起连接		1. 弹出提示「仅允许同时连接一台设备」（或等价文案）
2. 不建立与任一设备的通讯连接
P1多设备提示后断开至单台1. 两台设备同时接入并触发多设备提示
2. 物理断开其中一台（仅保留 A）
3. 重新进入连接 Ledger 流程并连接		1. 多设备提示不再出现
2. 完成与设备 A 的连接并进入 wallet 列表
P1连接过程中插入第二台1. 仅设备 A 接入并完成连接
2. 保持 A 连接状态下插入设备 B
3. 发起新建连接或切换设备		1. 检测到多台并存时弹出「仅允许同时连接一台设备」提示
2. 不允许在双设备并存下建立新的 USB 连接
P1USB 设备插拔后再次进入连接1. 两台设备并存触发提示
2. 断开 B，仅保留 A
3. 退出并重新进入连接流程		1. 设备数量恢复为 1 台后，提示消失
2. 可完成连接并继续添加 wallet/account

优先级场景操作步骤预期结果
❗️❗️P0❗️❗️网络已建立首地址锚点（如 BTC），切换不同助记词设备1. 用设备 A 在 BTC 添加首地址
2. 切换设备 B（不同助记词）继续在 BTC 添加账户		1. 拦截添加

P1未建立锚点网络（如 EVM 未添加任何地址）1. 先仅在 BTC 建立锚点
2. 切换不同助记词设备在 EVM 添加账户		1. 允许添加
2. 不触发设备不匹配
P1已建立锚点网络重复添加账户1. 在同一网络多次添加账户
2. 对比前后流程		1. 每次均按首地址 Hash 校验一致性
2. 结果稳定（放行或拦截一致）

1.4 BLE 标识、聚合与新建规则

优先级场景操作步骤预期结果
❗️❗️P0❗️❗️蓝牙可匹配且地址可匹配1. 用设备 A（蓝牙标识 X）创建 wallet
2. 使用蓝牙标识同为 X 且地址可匹配的设备添加 wallet		1. 先通过蓝牙匹配
2. 再通过地址匹配
3. 聚合到已有 wallet
P1蓝牙可匹配但地址不可匹配1. 用设备 A（蓝牙标识 X）创建 wallet
2. 使用蓝牙标识同为 X 但地址不可匹配的设备添加 wallet		1. 蓝牙匹配通过后进入地址匹配
2. 地址不匹配则创建新 wallet
P1蓝牙不可匹配1. 用设备 A（蓝牙标识 X）创建 wallet
2. 切换蓝牙标识为 Y 的设备添加 wallet		1. 不进入聚合路径
2. 直接创建新 wallet
P1BLE 分支稳定性回归1. 分别执行“蓝牙+地址都匹配”“蓝牙匹配地址不匹配”“蓝牙不匹配”三条路径
2. 重复执行 2 轮		1. 仅“蓝牙+地址都匹配”时聚合
2. 其余两种均新建 wallet

1.7 Ledger 安装 APP 主流程

优先级场景操作步骤预期结果
❗️❗️P0❗️❗️Onboarding 创建账户，BTC / ETH / TRX / SOL 四个 App 全未安装1. 连接 Ledger 并进入 Onboarding 创建账户流程
2. 保证设备上 4 个支持网络 App 均未安装
3. 观察创建账户前的安装引导		1. 弹出复选框选择需要安装的 App
2. 默认展示 BTC / ETH / TRX / SOL 四个可安装网络
3. 未直接进入创建地址流程
P1Onboarding 勾选多个网络安装1. 在复选框中勾选 2 个及以上网络
2. 确认安装
3. 观察安装过程		1. 按顺序逐个安装，不并行安装
2. 前一个安装完成后才进入下一个
3. 安装完成的网络可继续后续创建流程
P1投资组合创建地址时存在至少 1 个可用 App1. 进入网络选择投资组合创建账户流程
2. 保证 4 个支持网络中至少 1 个 App 已安装
3. 勾选多个网络继续创建		1. 不显示批量安装复选框
2. 仅对已安装 App 对应网络继续创建地址
3. 未安装 App 的网络不创建地址
P1投资组合创建地址时用户未勾选某待安装网络1. 在批量安装复选框中仅勾选部分网络
2. 确认安装并继续创建		1. 仅勾选的网络进入安装并继续创建
2. 未勾选网络不创建地址
3. 已创建网络列表不包含未勾选网络

1.8 单网络安装与异常场景

优先级场景操作步骤预期结果
❗️❗️P0❗️❗️单网络创建地址时目标网络 App 未安装1. 选择某单网络创建地址
2. 保证该网络 App 未安装
3. 继续创建		1. 提示安装对应网络 App
2. 安装完成后继续当前创建地址流程
P1单网络核对地址或签名时目标网络 App 未安装1. 发起该网络核对地址或签名
2. 保证目标网络 App 未安装
3. 继续交互		1. 提示安装对应网络 App
2. 安装完成后返回并继续当前核对地址或签名流程
P1投资组合创建地址按单网络交互处理1. 在投资组合中勾选多个网络
2. 混合准备“已安装”“未安装”网络
3. 继续创建地址		1. 每个网络按单网络交互顺序依次处理
2. 已安装网络逐个进入创建地址流程
3. 未安装且未完成补装的网络不创建地址
4. 前序已创建网络不因后续失败回滚
P1安装过程中断网1. 进入批量安装或单网络安装流程
2. 安装过程中断开网络		1. 显示网络异常或安装失败提示
2. 当前失败网络停止继续安装 / 创建
3. 用户可感知失败原因来自网络
P1安装时设备空间不足1. 进入安装流程
2. 保证设备剩余空间不足以安装目标 App		1. 显示设备空间不足提示
2. 当前目标网络安装失败
3. 不伪装为其他失败原因
P1安装过程中设备断线1. 进入安装流程
2. 安装过程中拔线、蓝牙断开或让设备掉线		1. 显示设备已断开或连接中断提示
2. 当前安装与交互停止
3. 前序已处理网络的创建结果保持有效
