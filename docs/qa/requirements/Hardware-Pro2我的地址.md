# Hardware - Pro2 收款（原我的地址）

> 模块：硬件钱包 / Pro2；对应Test：OK-54793、OK-54792，保留Jira原标题。
> 规则：docs/qa/rules/hardware-rules.md §14。
> 依据：2026-11-07用户确认新版交互；firmware-pro2 main d2b16b0f4b99a3380c2f87334226f0c0223ad402离线核对。

## 1. 收款入口与账户

1. 应用菜单进入“收款”，Account默认#1，网络改为纵向列表，不显示旧Title开关。
2. 网络共21个（原20个新增Zcash），名称与顺序见hardware-rules §14.2；保留Cosmos/Polkadot子链及已移除七网络不展示的校验。
3. Account选择每页5个，首尾翻页按钮不可点击；点击账户即返回网络列表。有效输入1至1,000,000,000，非法值清空并提示“无效的账户”，空值不能提交。
4. 同会话切换网络和路径保留Account；取消选择不改变原值。退出收款或锁屏后重新进入恢复#1。

## 2. 地址、二维码及路径

1. 同页显示网络名称、二维码及中央网络图标、Account与完整分段地址，底部“完成”返回网络列表；无需旧独立QR页或EVM说明卡。
2. 顶部派生入口打开选项弹层，选中唯一，选择后同页更新地址和二维码，取消不修改。
3. BTC：Nested Segwit/Taproot/Native Segwit/Legacy；ETH、SOL：BIP44 Standard/Ledger Live；LTC：Nested Segwit/Native Segwit/Legacy；Kaspa：OneKey Extended/Kaspa Official；Zcash：公开/隐私/旧隐私地址，默认展示公开地址。其他网络不显示切换入口。
4. Zcash以外不推断未确认的默认路径。App支持的路径与App同钱包同账户核对，扫码解析地址与屏幕完整地址一致。
5. Zcash设备支持三种路径，App只支持公开、隐私两种；旧隐私地址使用同测试钱包同账户的已核验离线参考结果，二维码独立解码。不得要求App第三种路径或把App同步要求写为设备端展示条件；标准及隐藏钱包均覆盖三种路径，切换不改变Account或钱包身份。

## 3. BTC新鲜地址

1. 点击BTC地址页Account，查看当前账户下地址序号及完整派生路径，选择后同页地址和二维码同步更新。切回与取消分别验证恢复及保持原选择。
2. Account账户编号与地址索引不同；新鲜地址只改变当前账户下的索引，不改变钱包身份、Account或其他网络结果。
3. 四种BTC路径类型都需验证；同钱包、同账户、同路径、同索引与App或离线测试工具对照。只使用测试种子。
4. 本需求可能尚未合入main；用例执行使用包含功能的构建，不以当前未实现判定产品不支持，不设定未确认的分页数量、索引上限或重启持久性。

## 4. 钱包身份及参数覆盖

1. 主PIN解锁始终显示标准钱包地址，不论Passphrase开关状态；全流程无Passphrase输入弹窗或切换入口。
2. Extra PIN解锁显示该PIN所绑定Passphrase的隐藏钱包。切换网络、路径、Account及地址索引不改变身份；锁屏换Extra PIN-B或主PIN分别显示对应隐藏钱包B或标准钱包。
3. Extra PIN与Passphrase分别配置，不把Passphrase样例用作PIN。标准与隐藏钱包均核对对应种子和派生结果；App未支持的Zcash旧隐私路径按第2节独立参考核对。
4. 保留旧来源矩阵：导入18位/#188、导入24位/#2024、创建12位/#12、创建18位/#18、创建24位/#24；12位导入由基础钱包场景覆盖。标准钱包及隐藏钱包各核对网络地址和二维码。
5. 英语、简体中文、繁体中文、日语、韩语、西班牙语、葡萄牙语（巴西）切换只改变界面文案，同身份、账户、路径和索引的地址及扫码结果不变。
