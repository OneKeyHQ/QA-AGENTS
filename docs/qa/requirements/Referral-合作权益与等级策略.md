## 1. 范围与版本

覆盖返佣首页、比例弹层和等级页；测试端为 iOS / Android / Desktop / Extension / Web。

- 6.7.0 及以上展示新增合作权益与等级策略信息；6.6.3 核对兼容后的实际比例，不要求出现新增提示。
- 三个概念独立：标准等级决定普通比例，Partner Plan 决定合作比例，Level Policy 决定升降级策略。
- 只在测试环境调整 Plan、策略和业绩；使用测试环境有效业务及比例配置，不修改生产用户。

## 2. Partner Plan

- 普通用户沿用标准等级比例及升级、保级提示。
- 关联 Plan 后，首页展示合作权益和实际比例；等级页分开展示当前比例与标准等级，不能用合作比例反推用户等级，也不能改写全局等级表。
- 硬件销售、合约、Swap、DeFi 的邀请人和受邀者两侧分别核对。支持跟随用户等级、跟随指定等级、自定义比例；未配置业务继续跟随用户等级，配置值不叠加、不自动取较高值。
- 自定义比例 0 为有效值，不能回退为标准比例；受邀者 0% 显示「—」。支持仅硬件邀请人使用钻石比例，其他业务及受邀者均为 0。
- 一个用户只关联一个 Plan，更换时整体替换；取消 Plan 恢复当前等级比例，保留原 Floor / Fixed。

## 3. Floor 与 Fixed

- Normal：按普通规则升级、保级和降级。
- Floor：显示「等级保护中」，配置截止时间时展示时间；可升级、保护期内免降级，保留升级进度，隐藏保级风险提示。到期退出保护展示，实际等级使用服务端结果，不将到期等同于客户端立即降级。
- Fixed：显示「固定等级」及不自动升降级的说明；隐藏自动升级进度和保级提示。当前无到期时间，须手动取消。
- 仅有 Floor / Fixed 不展示合作比例区块；与 Plan 同时存在时同时展示策略和合作权益。

## 4. 取消 Fixed 后立即重算

1. 后台将 Fixed 改为 Normal 并保存生效时，立即执行一次普通规则评估，不等新订单触发或下次每月 10 日考核。
2. 结果可高于、低于或等于原固定等级，也可以回到青铜；依据既有普通规则的统计周期、有效业绩和三业务线阈值，不默认恢复固定前等级。
3. 核对硬件、合约、Swap 任一达标及最高匹配等级，DeFi 业绩费不参与等级考核。本次不改变普通用户日常月度考核规则。
4. 保留原 Partner Plan：跟随用户等级的比例随新等级变化，跟随指定等级及自定义比例仍按 Plan；显式 0 仍为 0。
5. 保存后刷新或重入客户端，首页及等级页使用重算后的服务端等级，移除固定提示，按新等级恢复适用的升级和保级信息。最高等级不显示升级目标。
6. 仅编辑未保存、退出编辑、客户端刷新或重入不额外触发解除固定等级的重算。对同一次已生效解除操作，核对服务端记录只有一次重算；页面刷新请求不作为重算次数。
7. 重算等级与历史奖励重新计价是两件事：已记账订单金额保持，后续订单按生效时的实际比例记账。

## 5. 可复现数据与影响范围

- 升、降、保持、零业绩各准备独立 Fixed 测试用户。预先按现有普通规则确定统计周期及结果，并记录有效业绩、原固定等级、期望等级；避免测试跨越月度考核或同时写入新业绩。重算次数从服务端日志或业务记录核对，不能只凭 UI 推断。
- 比例使用彼此可区分的测试值，例如同一 Plan 内 Swap 邀请人 12%、受邀者 3%，并覆盖低于及高于标准比例的组合。示例不是生产默认值。
- 本次内容合并到 `docs/qa/testcases/cases/referral/2026-02-09_Referral-硬件销售奖励.md`，普通等级、历史订单与跨端场景合并去重；不保留独立等级用例。标准比例适用于 Normal 且无 Plan 的场景，新增例外统一见返佣规则 §3.1.4。
- 现有返佣 UI 自动化仅覆盖绑定邀请码，尚无本需求场景；现有 Apifox 返佣用例未包含 Plan / Floor / Fixed。此次不改写其既有断言，也不宣称已自动化覆盖。服务端立即重算、幂等和比例计算可后续下沉 API 自动化。
