# Referral - Swap 返佣

## 需求背景

OneKey 已有钱包邀请关系、返佣等级和 Swap 对账能力。本期把符合条件的 Swap / Bridge 订单接入现有返佣体系，并在邀请页面增加 Swap 奖励数据。

补充口径：
- KOL 与普通用户使用同一套返佣规则、等级、比例和客户端界面，不建设 KOL 专属规则。
- 对 KOL 的倾斜通过等级兑换码一次性提升当前等级；兑换后按统一业绩要求升级、保级和降级。

## 测试端

iOS / Android / Extension / Desktop / Web

## 一、返佣范围

| 维度 | 规则 |
|------|------|
| 邀请关系 | 沿用现有钱包绑定关系，仅计算直接邀请关系 |
| 用户规则 | KOL 与普通用户一视同仁 |
| 首期渠道 | SWFT、HiFi、ExodusBridge、Changelly、Houdini |
| 生效范围 | 仅统计新版本上线后、具备邀请归因的订单，不补算历史数据 |
| 不计返佣 | 失败订单、零手续费 / 零应收分成订单、白名单外订单 |

## 二、返佣比例

返佣基数为订单完成时后台提供的 **OneKey 应收分成**。不同渠道的分润方式和应收金额不同，实际返佣统一以后台逐单应收字段为准。

| 等级 | 邀请人 | 受邀者 | 合计 |
|------|--------|--------|------|
| 铜 | 10% | 10% | 20% |
| 银 | 15% | 10% | 25% |
| 金 | 18% | 10% | 28% |
| 钻石 | 20% | 10% | 30% |

计算方式：
- 邀请人返佣 = OneKey 应收分成 × 等级比例
- 受邀者奖励 = OneKey 应收分成 × 10%
- 示例：某笔订单 OneKey 应收分成 100 USDC，邀请人为钻石，则邀请人得 20 USDC，受邀者得 10 USDC

## 三、升降级

Swap 交易量作为统一返佣等级的并列考核条件，与硬件销售、Perps 交易量一致，满足任意一个业务线条件即可升级或保级。升级和保级使用同一门槛。

| 等级 | 当月有效 Swap 交易量 |
|------|---------------------|
| 铜 | < 60,000 USD |
| 银 | 60,000 USD ≤ 交易量 < 500,000 USD |
| 金 | 500,000 USD ≤ 交易量 < 1,600,000 USD |
| 钻石 | ≥ 1,600,000 USD |

门槛测算口径：Swap 等价交易量 = Perps 交易量 ÷ 10（按 OneKey 估算应收率 0.5% 对齐 Perps Builder Fee 0.05%）；金级门槛由测算值 200,000 USD 上调为 500,000 USD。0.5% 只用于门槛测算，实际返佣仍按逐单应收分成。

## 四、邀请链接与落地页

| 项目 | 规则 |
|------|------|
| 链接 | 邀请奖励页「更多链接」新增 Swap 项，路径 `/r/<邀请码>/app/swap`；顺序 硬件销售 → 合约 → Swap → DeFi |
| 落地页 | 主标题「你收到一份专属邀请！」；副标题「在 OneKey 进行 Swap，完成绑定即可获得 10% 手续费返现」；Step 3「进行 Swap，每笔自动返还 10% 手续费」，按钮「立即 Swap」 |
| 折扣值 | 与 Perps 落地页共用后台受邀者折扣配置，请求未返回前默认 10% |
| 落地页结构 | 头图 + 三步漏斗，不含 Perps 的优势区块与移动端亮点 |
| 唤起后 | 通过 Swap 链接唤起 App 并完成绑定后停留在 Swap Tab |
| Swap 页入口 | 桌面宽屏在页头礼物按钮，其余在 Swap 设置面板「活动中心」；仅 Swap Tab 显示，Bridge / 限价单 Tab 不显示 |
| 未绑定钱包 | 点击活动中心先弹绑定邀请码流程，绑定完成后再打开「Swap 奖励」弹窗 |
| 非 EVM 账户 | 弹窗提示「当前账户不支持。请连接一个 EVM 账户后重试」 |

## 五、客户端展示

| 页面 | 展示内容 |
|------|---------|
| 等级进度 | 当月有效 Swap 交易量、下一等级门槛及剩余所需交易量 |
| 等级页比例 | 「佣金比例（您 / 受邀者）」新增 Swap 行，与合约手续费同档位 |
| Swap 奖励汇总 | 待发放奖励（附 总计、下一次发放日期）、累计成交额（附 OneKey 费用）、受邀地址数（附 来自 X 个钱包） |
| 受邀人列表 | 地址、邀请时间、邀请码、首次交易、交易量、OneKey 费用、收益；待发放 / 总计 Tab；总计 Tab 有「隐藏非活跃地址」开关；支持时间与邀请码筛选、导出 |
| 奖励记录 | 由统一的「奖励发放历史」页面承载，按月分组，含代币、金额、交易哈希 |
| 受邀者奖励 | 「Swap 奖励」弹窗：已发放、待发放（> 0 才显示）、发放历史（日期、金额、交易哈希）；提示「奖励将于下个月 10 号之前发放到您的 Arbitrum 钱包（与以太坊相同的地址）。」 |

邀请人侧不展示渠道、From / To 币对和逐笔订单，避免暴露受邀者交易行为。

已确认口径：
- Swap 奖励无「确认中」状态。
- 受邀者侧发放历史为必需功能，客户端后续补上。

## 六、数据链路

| 阶段 | 处理 |
|------|------|
| 下单 | 客户端附加当前钱包的邀请绑定信息，不因绑定查询阻塞下单 |
| 订单完成 | Swap 服务保存订单和邀请归因快照 |
| 数据同步 | Swap 服务将订单、佣金和结算状态同步至返佣服务 |
| 返佣计算 | 返佣服务解析邀请关系并计算邀请人及受邀者奖励 |
| 状态变化 | 退款、订单修正和核销结果增量同步，以订单号保证幂等 |
