## 1. 交易、收藏与账户面板

1. 现货普通限价与 BBO 均进行 $10 最低名义金额校验；按实际精度规整后的数量判断。条件单低金额可点击并以 Toast 拦截，快捷填入区分 iOS 附件条与 Desktop / Android Toast。
2. 永续收藏先反映本地状态，并关联行情自选及已启用的云同步链路；不要求每次点击立即 HTTP，也不以无 HTTP 为验收条件。现货收藏与永续身份隔离。
3. 账户概览标题和比率名随默认、统一账户、组合保证金模式切换；仅使用与当前地址匹配的模式数据。MMR 颜色与组合风险等级分别验证。
4. 持仓操作顺序与可见性以《Perps-反手与持仓按钮设置》为准；iOS / Android 可配置，窄屏 Web 不因此获得该能力。

## 2. 图表、菜单与路由

1. 主图与移动全页图支持 TradingView / 原生版偏好持久化。原生 App 的原生版关闭绘图，非原生平台原生版提供独立绘图工具；compact 顶部 / 底部内嵌图保持轻量能力，不套用主图工具与交易叠加。
2. 原生版大屏交易菜单按多空方向与选择价相对中间价显示止盈或止损；价格相等、无仓位、现货时不显示持仓止盈止损。其菜单不要求绘制水平线项。
3. 底部浮层展开后原入口条隐藏，使用浮层收起控件关闭，收起后恢复上箭头入口条。
4. 大屏 Popover 直接展示偏好设置；小屏菜单按页面能力显示偏好设置、布局、历史、投资组合、帮助 / 指南快捷入口，活动入口按配置展示。移动端返回从持仓按钮设置到布局再到首页，短屏可滚动。
5. 裸基础币现货链接补 USDC 查找；不存在 USDC 市场时不能匹配到其他报价币。桌面七 Tab 与移动三交易 Tab + 四历史 Tab 分开验收。
6. Desktop / iOS / Android 主图或全页图未保存图表引擎偏好时，首次进入 Perps 默认使用原生图表；已经保存的 TradingView / 原生版偏好继续保留，不因默认值调整被覆盖。来源：2026-11-04 用户确认「默认的图表模式需要是原生图表」。移动端默认原生已于同日由用户进一步确认。
7. Perps 原生主图 / 全页图执行整套指标重置并确认后，必须恢复并显示默认成交量 VOL；重置前手动关闭 VOL 也应恢复。指标面板选中状态与实际 VOL 副图均需核对，不能仅检查名称存在。用户于 2026-11-04 确认「重置之后也需要把默认的 vol 显示，已提交 bug」；缺陷编号未提供，未声明已修复。单指标参数重置、视图缩放还原和 compact 内嵌图不套用整套指标重置预期。

8. TV与原生引擎的绘图各自独立保存；双向切换不清空、修改或污染另一引擎的对象，不要求跨引擎迁移绘图。同一Perps模块两种引擎共用且支持的周期按最近一次选择；TV独有3m / 2H / 8H / 12H / 3D切到原生回退1H，用户确认此差异为预期。
9. 指标数值输入的端差异为已确认预期：Desktop可解析科学计数及去逗号后的数值；移动端仅接受普通十进制格式，其他格式保留原有效值。共同执行有效值回退、边界限制和步长规整，不据端差异报告缺陷。
10. 成交标记按成交时间定位到对应K线，蜡烛图在高点上方、折线图在收盘点上方；提示展示成交方向、数量及价格。同一K线最多绘制10个标记，超出不绘制，不提供聚合或更多入口；视口裁切可使可见数量少于10。Q02 / Q03已由用户确认，不沿用TV成交价纵坐标预期验收原生。
11. 图表加载使用QA受托定义的项目初始标准，见 `docs/qa/rules/perps-native-chart-performance.md`；阈值制定不等同实机通过。

## 3. 历史成交

1. 类型、买卖方向与市场筛选取交集；类型变化清空市场，账户变化恢复全部筛选。DEX coin 保留身份；现货市场筛选按基础币聚合，列表 / 详情保留完整报价币。
2. 详情对照原始成交的价格、数量、方向、maker / taker、成交前仓位、手续费币种、构建者费、订单号和哈希。USDC 手续费可扣减美元平仓盈亏，代币手续费不得直接扣美元金额。
3. 非零已实现盈亏、非现货、非强平成交可分享；普通平仓与反手分别验。反手不能使用包含新开仓部分的总量反推旧仓成本，不能把缺失开仓价和 ROE 填成 0。
4. 历史分享 ROE 不应随当前设置杠杆变化；该行为是用户已提交的缺陷 R01。回归以同笔历史成交在修改当前杠杆前后保持一致为判定，不擅自规定未经确认的缺失历史成本展示方案。

## 4. 现货碎币自动兑换

1. UI 开启对应服务端 optOut=false；关闭对应 true。状态必须与当前地址匹配，且账户 canTrade 才可修改。
2. 未加载 / 地址不匹配 / 无交易权限禁用；写入 pending 按地址隔离且防重复。拒签、失败后结束加载并恢复服务端状态，可再次操作。
3. 请求中换账户不将旧账户 pending 状态或成功提示注入新账户；重新进入后按各自服务端值显示。
