# 手动用例与 Jira / Xray 同步流程

适用于在本仓库新建、补充、修改手动用例的所有人和 AI；不依赖某个 AI、插件或连接器。格式入口为 `docs/qa/qa-rules.md` §7.3，编号映射唯一来源为 `docs/qa/jira-test-mapping.json`。

## 交付与询问（强制）

1. 先完成仓库 Markdown 用例及可复制 HTML，验证两份内容、优先级、条数、章节与单元格换行一致。可复制区域只保留前置条件和用例内容，不带文档头元数据。
2. 按本次变更的文件路径查映射，读取已映射 Jira Test 的当前内容，对比待更新范围；将目标编号、链接、变化摘要及未映射文件列给用户。读取不代表同步，不把需求、Story、Bug 编号当作 Test 目标。
3. **交付后主动询问一次：**「用例和可复制版已更新，是否帮你同步到对应 Jira 用例？」批量变更一次询问即可，明确本批目标。用户未回复时只保留本地成果；用户说不用时，本批不更新、不创建 Jira，也不反复询问。
4. 用户同意本批同步后：有已核实映射的直接更新对应 Test，不再逐个确认；没有映射的询问「请提供要覆盖的 Test 编号，或确认创建新的 Test」。允许先完成本批已映射项，未映射项留待回复；不能凭相似标题擅自覆盖或自动创建。
5. 用户在当前会话已明确授权这批具体 Jira 目标和修改范围时，沿用授权，不重复询问。泛指「修改用例」「生成可复制版」不代表授权写 Jira；映射文件也不保存用户的永久写入授权。

这是手动用例交付流程的最后一步，不受「默认工作流不要再问」影响。用户要求只修改本地时，直接遵循其选择。

## 更新目标与正文

- 写入前核实站点、issue key / id、项目及类型 `Test`，再次读取当前内容；若远端自预览后被他人修改，先合并并展示冲突，不能直接覆盖。
- 当前映射采用「一份用例文档 → 一个 Jira Test 的 description」；表格行不单独创建 Test，历史文档不参与同步。以源文件中的前置条件和用例正文构造更新内容，与可复制版相同；保持四列、章节、优先级、步骤编号及真实单元格换行，不能直接上传 HTML 页面脚本或粘贴可见 `<br>` / `\n`。
- `description` 与 Xray 的 Test Definition / Manual Steps 是不同位置。当前映射只核实了描述正文；若实际要更新结构化 Steps，先读取测试类型、步骤和可用接口，再确认目标存储位置并更新映射，不能把改了描述声称为改了 Steps。
- 默认只改映射声明的正文字段；保留 Jira 标题、负责人、状态、标签、链接、执行记录及目录归属。若正文含仓库未管理的额外内容，先合并保留，范围不明确时询问，不能整段丢弃。
- 没有映射时，用户提供已有编号后先读取并核实内容归属；编号不是 Test、属于另一主题或已被其他文件占用时，说明冲突并询问。创建须获得本批授权，先核实项目、Test 类型和目录位置；未知目录不能冒称已加入。创建结果不确定时先查是否已创建，避免重复创建。
- 优先使用可用的 Jira / Xray 连接器；连接器不支持的目录或 Steps 操作可使用已登录 UI。缺少登录、权限或接口时，保留本地成果与待同步清单，说明具体阻塞，不把「可自动更新」说成「已更新」。

## 映射维护与回读

`docs/qa/jira-test-mapping.json` 为版本化、无凭证的项目共享数据，不存 AI 私有记忆。

- `mappings[]`：`file` 为仓库相对路径；`issue_key` / `issue_id` / `remote_summary` / `issue_type` 为已读取的远端身份；`body_field` 为实际更新位置。
- `identity_verified_on` 只表示文件与 Test 归属已核实；`remote_updated_at` 是读取时远端修改时间；`comparison` 是核对快照，不能代替下次实时读取。
- `last_synced_at` 初始为 `null`，只有写入后回读验证通过才填写，同时更新已同步源文件和远端正文的 SHA-256。身份核对、用户同意、提交写入请求都不等于同步完成。
- `repository_folder.membership_verified=false` 表示目录成员尚未读取；不能根据标题搜索结果将其改成 true。`unmapped_remote_tests` 是已发现但缺少同主题源文件的 Test，不作为其他文件的覆盖目标。`excluded_files` 记录已被替代的历史源文件。
- 文件重命名、拆分、合并时一并维护映射，禁止两个活动源文件未经明确分区约定覆盖同一个 Test。新建或指定编号后必须把已核实关系写回映射。
- 每个目标更新后重新读取实际正文，逐章节、逐表格检查条数、四列内容、编号与换行；必要时在 UI 核对富文本。只对验证通过的目标记录同步时间；失败项保持待处理，报告部分完成，不自动删除远端用例。
- 富文本同步使用连接器支持的 HTML 正文片段（如 `contentFormat: html`），表格单元格内多行用段落或真实换行节点。回读应取得 `renderedFields.description`（如读取时展开 `renderedFields`）或原始富文本节点再核对；默认 Markdown 摘要可能压平换行，不能据此判定写入后的排版。HTML 源码中标签间的缩进换行会折叠，校验时不能把它与 `<br>` / 段落边界重复计数。
- 更新片段只使用连接器文档支持的属性，不能直接带网页的 `class="note"` 等展示类。花括号占位文字可能触发 Jira 宏解析并插入段落：面向执行者的描述优先写成「所选代币」等实际含义；确需保留字面占位符或 `--` 等易被 wiki 转换的符号时，使用支持的行内 code 并回读确认。不得放宽编号、符号或换行校验来掩盖渲染差异。
- 最终交付源文件、可复制版、映射及同步结果（已更新 / 用户跳过 / 无映射待确认 / 阻塞），并检查对 API、UI 自动化的影响。同步描述和映射本身不修改自动化断言。

## 跨 AI 入口

`.claude/CLAUDE.md` 是仓库全局指令真源，根目录 `AGENTS.md` 与 `.cursorrules` 通过软链读取；Test Designer 的 Codex、Claude、Cursor 入口均引用本文。新接入的 AI 应读取这些仓库指令，不能只读某个历史技能模板。规则和映射需提交到共享分支并由协作者拉取后才能在其环境生效；仅本地修改或未读取仓库指令的工具无法保证触发。
