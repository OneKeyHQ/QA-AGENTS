# Zcash / Monero HD 钱包转账与隐私同步规则

## 1. 适用范围与确认依据

适用于 Zcash、Monero 的 HD 钱包及与HW账户共享扫描身份的管理场景；与 `transfer-chain-rules.md` 中 Zcash HW 的六条简化转账用例分开维护。依据为 2026-11-07 原需求及 2026-11-11 用户确认的双重上限、历史地址展示和审查建议补充。源码参考 app-monorepo `x@c1d2ab0d31a7bf45b758b308d94c453f9febd370`，未确认的实现细节不作为新需求。

## 2. 地址与转账

1. Zcash 仅 ZEC 主币，无代币；公开与隐私地址分别核对。沿用本链已确认的最小值 0.00000546 ZEC、中间测试值 0.01 ZEC 与 Max，覆盖四个地址方向；Max 核对确认页金额及实际费用。
2. 隐私使用与发送前同步至最新区块；接收后再同步核对入账。不开启、暂停或进行隐私同步，都不应阻塞公开地址、公开余额、公开历史及公开转账。
3. Monero 两条派生路径各执行真实转账，不能用同一个地址替代：标准 `m/44'/128'/0'`、Cake Wallet `m/44'/128'/0'/0/0` 为索引 0 的实例。其他索引替换账户索引，地址、余额及本地历史按派生账户归属。
4. Monero 在同步或发送需要密钥且未获得授权时唤起解锁；取消不广播、不扣款，也不启动该次需密钥的同步。再次授权后可继续；不要求持有有效授权时每轮后台同步重复弹出解锁。
5. 公开 → 公开交易可核对区块浏览器；涉及隐私的交易只核对本地历史；接收方自己的地址无需隐藏，展示本账户收款地址，无法识别的对手方显示「隐私」。不以外部浏览器可查询作为隐私到账条件。

## 4. 账户管理、同步上限与开启上限

1. 两个入口：「设置 → 钱包 → 隐私管理」、「钱包选择器 → 隐私同步」。比较同一钱包、网络和账户的状态，不要求全局列表与钱包过滤列表相同；账户卡片核对钱包、名称、派生类型和状态。
2. **同步上限**：所有隐私链共享五个同时同步名额，限制来自 CPU 解密压力。目标链未触及开启上限时，新账户可开启并暂停一个旧账户，旧数据保留；不写死旧账户选择顺序。
3. **开启上限**：每条链最多五个保留本地隐私数据的开启账户，因每链共用 4G 存储空间。该链第六个新账户被拦截并提示删除旧账户本地数据，不能静默替换。暂停只释放同步名额，不释放开启名额；不同扫描身份（含不同钱包及 Monero 派生地址）计入所属链，不按钱包分别获得五个名额；同一密钥的 HD/HW 账户共用一个扫描身份、名额及数据。
4. 删除取消不改变旧数据或名额；确认删除一个旧账户本地数据后才释放一个开启名额。新旧账户重新开启均受上限约束，需选择恢复起点并完成所需授权；删除不删除钱包、地址或链上资产，其他扫描身份不被串改；同扫描身份的账户共享启停与数据，删除会联动。
5. 开启上限按链独立；一链已达五个不能阻止另一链开启。两链各五个可保留数据，但同时同步仍合计最多五个。上限以不同扫描身份的数量验收，不要求填满4G或达到某CPU占用率。
6. 两类上限场景集中在 Zcash HD 第4节，以 Zcash / Monero 分别代入；Monero文档引用，避免重复维护。

## 5. 同步维护与发送补充

1. 修改已有账户起点须区分取消与确认，确认后从新起点重扫；网络级存储重置仅重建目标网络数据，按保存起点恢复，暂停账户不自动开启，另一网络不被清除。重建后余额和历史不重复。
2. 原生端验证等待 Wi-Fi、允许移动数据与恢复网络后的继续；节点异常显示等待或错误，恢复后从已有进度继续，不新增浮窗。不写死移动数据默认值或后台策略。
3. 私有发送须满足同步就绪；暂停或未就绪不广播、不扣款，恢复后可进入确认。Max只使用当前来源的可用余额并计入网络费，金额修改及重算后确认页使用最终输入，不沿用旧金额或费用。具体区块容差、输出解锁规则不从源码反写成需求。
4. Zcash软件钱包补充隐私收款可选Memo：空值、有效文本/HEX、无效HEX拦截和修正；公开收款不携带隐私Memo。此项不扩展HW解析范围。

## 6. 本轮确认的界面与状态分支

1. 满额提示可在弹窗内查看占位账户、派生分组、共享身份和启停状态，直接删除需二次确认。取消不释放名额，确认后显式重试新账户；未展开的隐藏钱包不暴露具体地址或名称，Extension小窗列表可滚动。
2. Monero首页覆盖未开启、暂停、首次创建地址后承接开启；资产组合选择的未保存草稿按钱包/账户隔离，取消开启不提前保存偏好或启用同步。
3. 扫描发现新资金不等于已验证可用；软件密码或硬件设备验证前先说明待验证资金。取消不广播、不增加已验证可用额，验证后更新可用余额及Max；不要求被动进入发送时弹密码。
4. Zcash隐私发送进入金额页后等待本次扫描完成，不用旧同步完成/0剩余区块代替；输入金额不重启扫描，公开来源不受隐私等待阻塞。Monero保留自己的发送就绪规则，不照搬Zcash本轮扫描条件。
5. 已开启账户准备阶段可暂停；控制请求期间防连点、面板跳变、旧账户结果回写，账户切换或错误后以当前状态为准。

6. Zcash不支持私钥/xprv导入和xpub观察，仅支持t1公开观察地址；观察账户不能隐私扫描或签名发送。HD与受支持硬件账户仍可用，四条边界集中于Zcash软件钱包第7节，共用OK-23804。
