# Perps 原生图表加载验收标准（v1）

> 2026-11-04：用户要求由 QA 先定义图表加载定量标准。以下为项目初始验收线，不声称行业统一标准；后续实测另报结果，不能把阈值制定当作性能通过。
> 适用：Desktop 原生主图与 iOS / Android 原生全页图；compact 单独记录，不把完整指标加载时间套到轻量图。TV 如需使用同一性能线，另行明确。

## 1. 耗时阈值

| 场景 | Desktop P95 | iOS / Android P95 | Desktop 单次上限 | iOS / Android 单次上限 |
| --- | --- | --- | --- | --- |
| 首次进入、当前市场行情缓存未命中 | 3秒 | 4秒 | 6秒 | 8秒 |
| 切换交易对或K线周期 | 2秒 | 3秒 | 4秒 | 6秒 |
| 切换至原生图表引擎 | 3秒 | 4秒 | 6秒 | 8秒 |
| 原生图进入或退出全屏 | 0.5秒 | 0.8秒 | 1秒 | 1.5秒 |

## 2. 测量方法

1. 起点：用户点击对应入口、目标交易对、周期、引擎或全屏按钮的时刻。首次进入不包含应用启动、密码解锁和首次路由前的等待。
2. 终点：目标市场和周期的可用K线已绘制，价格轴与时间轴可读，已启用指标完成可见绘制，加载遮罩不再阻挡操作，首个十字线／触摸交互产生对应反馈。单独记录“首根K线可见”时间，不拿它替代完整可交互时间。
3. 全屏切换终点：目标布局完成，行情及所选指标可读取，首个交互可响应；不计入该动作前的行情首次加载。
4. 使用单调时钟或同一录屏时间轴测量起终点；固定市场、周期、指标集合、窗口／设备、包版本。Desktop与移动端、iOS与Android、冷缓存与热缓存分别统计。
5. 每个场景每端至少20次有效样本，P95按排序后第ceil(0.95×N)个样本取值，同时报告N、P50、P95、最大值及超时数。两类阈值必须同时满足；未完成或超过上限的样本计失败，不能删除或仅按已完成样本计算通过。

## 3. 标准环境及异常样本

- 固定测试设备与包版本，无并行自动化、人工操作或CPU／内存压力任务；记录系统、设备型号及实际指标数量。
- 使用可达行情服务的稳定网络：可用带宽至少20Mbps，到实际行情服务RTT不高于100ms、丢包低于1%；不满足时记录环境不达标，该批不出标准环境的合格结论。弱网与断网结果另列。
- 冷缓存测试仅使用独立配置且不删除用户数据；热缓存测试先加载目标市场后再采样。冷／热样本不能混成一个P95。
- 只读叠加账户数据独立报告，不把账户历史请求的完成作为市场K线首屏终点。错误交易对或空图即便耗时短也不算加载完成。
- 数据源报错、限流、断网、真实无历史数据及其他阻塞全部保留记录并分类；预先定义的非标准环境样本单独成组，不事后按耗时选择性剔除。

## 4. 与其他验收的关系

本文仅定义图表加载与布局切换耗时，不定义滚动惯性、FPS、重绘闪烁或主观“丝滑”阈值。功能用例验证重置后的状态、行情、指标及视图；Jira原问题作为审查依据保留，不把每个缺陷现象改写成独立验收条款。
